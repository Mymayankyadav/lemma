# Tutor keyboard research

## What carries over from Gboard

| Interaction | Primary evidence and Lemma behavior |
| --- | --- |
| Suggestion strip | Gboard offers words as you type and lets you keep an unfamiliar spelling. Lemma places the strongest of three choices in the center. When it offers a spelling correction, the original appears on the left. Choosing that spelling or immediately undoing a correction with Delete keeps the spelling for the open composer. [Gboard Help](https://support.google.com/gboard/answer/7068415?co=GENIE.Platform%3DAndroid&hl=en) |
| Key preview and feedback | Lemma enlarges the pressed glyph above the finger, keeps edge previews inside the keyboard and shows the alternate digit during a hold. The keyboard uses the app’s Haptics setting. Android’s open-source LatinIME provides the key-preview reference, and Gboard’s help describes long press and vibration. [Android LatinIME](https://android.googlesource.com/platform/packages/inputmethods/LatinIME/+/refs/heads/main/java/src/com/android/inputmethod/keyboard/MainKeyboardView.java), [Gboard Help on long press](https://support.google.com/gboard/answer/2842292?hl=en), [Gboard Help on vibration](https://support.google.com/gboard/answer/6102154?hl=en) |
| Touch and caret | The entire contiguous key cell responds, including the space around an inset keycap and the outer edge of the staggered middle row. Holding Delete repeats it. Sliding on Space moves the caret by grapheme. Google’s spatial model research describes learned key-center offsets. Lemma uses fixed hit cells and local QWERTY adjacency for spelling suggestions. [Google’s Gboard spatial model paper](https://research.google/pubs/spatial-model-personalization-in-gboard/) |
| Vocabulary | Google reports that unfamiliar vocabulary affects its keyboard models. In Lemma, checkpoint text and previously typed words supply spellings for a word already started. Six familiar lowercase prose typos can be corrected on a separator. Token boundaries, explicit TeX, names and kept spellings constrain those edits. [Google’s out-of-vocabulary research](https://research.google/blog/improving-gboard-language-models-via-private-federated-analytics/) |

Google’s published task-specific language-model measurements concern Gboard’s own spelling and next-word tasks. Lemma’s typed suggestions use a local dictionary and deterministic edit rules. The drawing model loads only when the learner opens **Draw symbol** with the beta enabled. [Google’s mobile language model research](https://research.google/blog/synthetic-and-federated-privacy-preserving-domain-adaptation-with-llms-for-mobile-applications/), [Gboard next-word prediction paper](https://research.google/pubs/federated-learning-for-mobile-keyboard-prediction/)

## Mathematical input

Touch entry uses Lemma’s custom keyboard. Hardware keys and IME use the same editor and undo history. The alphabet offers ∀, ∈ and ⇒ directly. **Maths symbols** opens the category keys, and **Browse symbols** searches names, TeX commands and shape descriptions with typo tolerance. The category grids use up to three rows, with two pages for prose scaffolds. A scaffold such as **Let … ∈ …** inserts `Let □ ∈ □.` with both slots open. The learner can jump between slots before sending.

Typed suggestions complete a started word, offer exact aliases on a tap, or reformat an explicitly supplied shorthand line. For example, `prei` can become `preimage`, `for all` can become `∀`, and `let x in A` can become `Let x ∈ A.` A quantified line such as `for every x in A, P(x)` carries the named predicate into `∀x ∈ A, P(x)`. `subset` offers both ⊂ and ⊆. The learner supplies the mathematical content of every rewrite. Proposed edits record their source spans, target range and editor revisions. Accepting one applies a single edit at the saved selection and preserves surrounding text. [Completion policy tests](../../../tests/unit/tutor/input-completion.test.ts)

## Drawing a symbol

**Settings → Tutor → Math input beta → Draw single symbols** enables recognition. **Draw symbol** opens a pad for one glyph at a time. A spinner sits in the compact results row while the model prepares. The row has up to three choices in each accessible group. **Matches** describes the current strokes, and **Could become** offers compatible extensions such as ≤ after drawing <. A tap inserts the chosen glyph and returns to the previous keyboard view. With **Keep drawing**, the pad stays open for the next glyph. Clearing or changing the drawing, changing the editor target or interrupting the pointer invalidates stale results. [Symbol input browser tests](../../../tests/e2e/v7-tutor-symbol-input.spec.ts)

The catalogue is local and offers name or TeX search, categories and recent choices for the open composer. It contains 153 symbols. The worker maps 136 of Detypify’s 411 classes by exact glyph and label, and keeps unmapped scores in the ranking evidence. Geometry also offers <, >, = and ≠ as explicit choices. A selected symbol inserts as Unicode in prose or in its canonical TeX form inside explicit math. [Symbol catalogue tests](../../../tests/unit/tutor/input-symbol-catalog.test.ts)

The current beta requires a tap for every insertion. Automatic insertion has a separate preference and requires model calibration, audited completions and held-out error measurements. The production Chromium checks exercised real model inference, a verified-cache offline restart and manual selection with missing or altered assets. An Android-mode bundle initialized in desktop Chromium. Installation in a physical Android WebView, phone latency, representative handwriting accuracy and native haptics remain unmeasured. [Runtime validation](../../../public/models/tutor-symbols/detypify-0.3.0-lemma-v1/README.md)
