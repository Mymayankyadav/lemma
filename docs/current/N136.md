## N136 v7 UX audit r3: launch and back feel like Android (AN3 · AW7, AW8) (13 Nov 2026)

Two of the audit's Android "feel" findings that needed no decision (`03` §4):

- **AW7 Launch.** The app hid the splash as soon as its native layer started, which could be before React had drawn
  anything, and the WebView kept its default white background until the page painted (a light frame on a slow start at
  night). The splash now lifts once React has drawn into the page root (`whenRootPainted`, `src/platform/splash.ts`; the
  static web splash that `index.html` ships inside #root does not count); the
  plugin's `launchShowDuration` (800 ms, auto-hide) stays the cap. `MainActivity` sets the WebView's background to
  `lemma_paper` from the Day/Night resources at start and on every configuration change (uiMode is handled by the
  activity, so a theme change does not recreate it).
- **AW8 Back on Today.** The App plugin's back callback was always on, so Android could not play its predictive
  "back to home" preview although the manifest opts in. The web layer now calls `App.toggleBackButtonHandler` as the
  route and layers change (`wantsBackHandler`, `src/platform/links.ts`): off on Today with nothing open, on everywhere
  else or with a sheet, dialog or menu open, so Lemma's own order (close the layer, go back, go to Today) is unchanged.
  From Android 12 the system then moves the app to the back, as `minimizeApp` did. Before Android 12 it would finish
  the activity, so `MainActivity` adds a fallback callback there (`BackPolicy`) that moves the task to the back; added
  without a lifecycle owner, it sits under the App plugin's callback and runs only while that one is off.

Device checks 3 (dark theme, force-stop, open: no light frame) and 4 (a slow back gesture on Today shows the home
preview) in `CHECKLIST.md` still need a phone.
