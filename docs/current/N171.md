## N171 Adaptive scheduler in the React app (Owner task)

The app now reads the per-user `settings.flags` introduced in N169. With every adaptive flag off, the existing screens render and no adaptive fact/cache reads run. No global flag, dependency, migration or server file changes.

- `scheduler_v2`: legacy, v6 and v7 plan/checkpoint views distinguish deferred and skipped checkpoints and deferred steps. They show the stored reason (`prune`, `prune:approved`, venture reasons) and date in the owner's time zone. Deferred steps do not receive current/completed markers.
- `recheck_v2`: project and Today lists show open due/overdue rows from `rechecks`, with concept, level, due date and prompt. Retired checkpoint recheck badges, prompts and dates are hidden under this flag.
- `time_block`: Today shows deadline, last study day, study days remaining (inclusive), gross capacity and logged time today. The daily queue shows eight entries and `+N more`, plus the shared optional tail. Infeasibility says `short by N min` and/or `core at risk`, linked to the plan.

`src/data/adaptive/` loads owner-scoped rows using the existing browser client. Its bounds and filters follow MCP `loadRows` (1,000 for fact families, 5,000 nonvoid evidence, 500 recent intervals/busy blocks, 2,000 due cards). The hook passes one captured clock to the reader and the imported pure `assemble`; time/recheck/plan/prune/queue/facts calculations are reused, not copied. All modules bundle in the production Vite build. The existing pure FSRS JavaScript engine needs only a browser declaration; its implementation is unchanged. Owner-change invalidation and a one-minute mounted refresh update the read model after connector activity/undo and while time is running.

Read-only: no commands, fact edits or cache refresh writes. The recheck list reads the server's derived cache as requested; the queue and feasibility are recomputed from facts. No real study data was queried or copied into tests. N170 (#1493) remains unmerged and its learning-profile columns are absent from main, so the conditional learning-profile card/approval is skipped.
