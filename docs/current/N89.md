## N89 — MCP notification controls without transport credential disclosure

MCP now exposes owner-filtered, bounded reads for notification history, quiet holds and safe device metadata. No endpoint, p256dh, auth or notification transport facts are included in responses or device command receipts.

An additive migration versions existing push_devices and notify_holds rows; real browser subscriptions remain the only way to register devices. A registered notify_command accepts device rename/disable/restore with optimistic versions and idempotent receipts, and hold create/update/delete with optimistic versions, idempotent receipts and undo_action journalling. Device changes are deliberately never journalled: the existing push subscription credentials must not be copied to action_changes.

The existing notify_act snooze/dismiss behavior remains in place. The new hold version trigger also detects changes from that flow; it does not replace the action semantics. Notification history is read-only for MCP; the connector cannot create, schedule or deliver notifications.

Coverage: tests/mcp/sql/notify-command.mjs (PGlite security, replay, conflicts, hold undo, device secrecy and existing notification actions); tests/unit/mcp/notify-coverage.test.ts (credential-free reads, scoped queries, connector routing); tests/mcp/sql/parity.mjs (both registered operation families). Independent SQL review required before the migration deploys on merge.
