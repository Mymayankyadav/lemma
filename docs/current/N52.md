## N52 — auditable timer modes and focus exclusions (PR #1103)

- One additive timer migration captures owner preset or settings defaults on first start, plus Pomodoro/Flowtime/open phases, owner-scoped device leases, journal/undo and reasoned exclusion spans.
- Consecutive integer-minute exclusions while a focus interval stays open use the latest exclusion boundary until a whole new minute of focus has accrued. This prevents millisecond slivers splitting the audit ledger between back-to-back requests and avoids double-counting.
- The PGlite regression covers two consecutive ten-minute deductions, exact 600/1200-second totals, owner isolation, idempotent receipts, takeover, and undo. Release remains gated on PR CI and independent production SQL review.

- Independent review found that the original lease-only trigger allowed direct authenticated updates to captured config and excluded focus without a lease or after expiry. The trigger now rejects any direct authenticated mutation of server-managed timer metadata or a started entry's preset, regardless of lease; a caller cannot bypass it by pre-setting lemma.tool. The owner-verified compatibility command body runs with SECURITY DEFINER to distinguish trusted RPC/undo DML from browser DML; all old owner JWT and explicit owner selectors are retained. New PGlite cases assert blocked config/ledger/phase edits with no lease, forged metadata and an expired lease, unchanged row/journal counts, while existing command/undo tests still run.

- After reviewing exact-head SQL CI, added an UPDATE OF trigger on the new timer metadata fields. PostgreSQL fires it even for a no-op assignment (for example an empty exclusion ledger set to the existing empty array), so authenticated direct writes are refused before journal mutations, even when the value-comparison trigger would see no difference. Existing regression still asserts rejection for that no-op, forged provenance and expired-lease writes.

- Preserved the historical active-lease error signature as well as the new protected-metadata error signature, so existing lease rejection tests and the new direct-write regressions both assert stable failure reasons.

The independent review found a forged session `lemma.tool` bypass in the interval trigger. N52 now checks the effective SQL role (`current_user`) instead of caller-settable provenance. Authenticated owner attempts to update, delete and insert leased intervals with forged `lemma.tool` and `lemma.source` are rejected, and tests assert no row or journal mutation. Owner-validated command and undo still execute as security-definer functions.

N52 fully extends N51 study_command compatibly with take_lease, next_phase and exclude_minutes. The owner-validated helper locks rows, checks expectedVersion and operationId reuse, journals each action, and exposes the unchanged registered MCP dispatcher. Captured preset or settings focus_defaults remain unchanged after the first start. Pomodoro alternates focus, short breaks and periodic long breaks; Flowtime derives its break from measured focus and the captured ratio; open mode never invents a deadline. A lease generation conflicts older devices and legacy study/interval writes until explicitly retaken or expired. Exclusions consume only the rightmost unexcluded union of absolute focus intervals with reasoned spans, refuse overdraw and restore exactly through undo_action. Full PGlite coverage includes mode transitions, owner isolation, version/replay conflict, lease takeover, legacy operation compatibility, forged browser metadata/interval DML, immutable start configuration, exclusion arithmetic and undo. A separate old presets fixture bug (#1110) was resolved by its owner. Production deployment remains gated on independent review and required CI, not by this document.

- Expired-lease takeover security fix: the UPDATE guard cannot protect INSERT. An authenticated BEFORE INSERT trigger now rejects fabricated running/paused entries or any non-default server timer state even with forged provenance; draft preset selection and legacy manually saved entries remain allowed. Added PGlite owner-RLS regression for forged running and draft metadata inserts, unaffected row/journal counts and the succeeding audited start path.\n
