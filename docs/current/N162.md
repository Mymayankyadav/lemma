## N162 — a paused timer no longer keeps running after the app is reopened

**Owner task** (14 Nov 2026, phone screenshot of a paused Pomodoro): "Timer keeps running still paused. I started the timer then paused and when the app was cleared from the memory the timer kept going when I restarted the app. Second why when I start timer from claude it does not create a notification right away. I have to open the app to have time in notification."

**Cause (first part).** A timed phase (Pomodoro, Flowtime) stores one `phase_ends_at`. The `study_command` pause and resume (and the demo store) never move it. The clock read it as it was, so a paused countdown kept running, and every reopen of the app showed less time (the screenshot: "PAUSED 21:32 · ends 17:18"). A resumed timer jumped ahead by the time it had been paused.

**Fix.** One pure function, `timedPhase` (`src/data/study/phase.ts`), reads the pauses from the intervals the server does keep: a pause closes the focus interval and a resume opens the next, so each gap between two focus intervals of the phase is time the phase did not run.
- Paused: the clock is frozen at what was left when the interval closed, and no end time is shown ("ends hh:mm" is gone until it runs again).
- Running: the end is `phase_ends_at` plus the phase's earlier pauses.
- A break phase and open sessions are unchanged.
It feeds the Focus clock and chime (`src/app/v7/focus.ts`, `FocusV7`), Today and the dock, the v6 Focus dialog and the Today card, and the Android notification's state (`src/platform/timer.ts`: no end time while paused, the shifted end once resumed). It needs no migration, so it also reads sessions that were already paused and resumed. If the server later moves `phase_ends_at` itself on resume, this function must stop adding the pauses.

**Tests.** `tests/unit/study/phase-clock.test.ts` (running, frozen however long ago it was paused, resumed after a pause, paused twice, break and open unchanged, the native state); `tests/e2e/v7-n162-paused-timer.spec.ts` (a paused Pomodoro opened 3 hours later still shows the same time and no end time; a resumed one counts its pause).

**Not done: the second part (issue #1408).** A timer started from the chat connector reaches the server only. The phone's notification is built by the app when it is open, and nothing pushes to the phone, so it appears only once the app is opened. Fixing it needs a push path (the same gap as N160.10) and an Owner decision on it.
