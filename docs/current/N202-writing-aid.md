## N202 local writing aid and physical-device preview

The owner explicitly continued PR #1738 with the previously researched writing aid, a theme-matched composer, interaction simulations, and a separate test APK before release. This extends the existing N202 input work in the same claimed PR; it does not start a second queue item or authorize production merge.

The owner's next revision supersedes the fixed review row and More panel. The composer now strikes through the proposed source and floats a compact tap-to-accept card above the input. The card has refresh and dismiss controls; a right swipe in the input accepts the faded continuation. The three stationary word targets prefer distinct word families, and the keyboard has a refresh button. An accepted edit has nearby Undo. Declining an edit suppresses that occurrence as typing continues; deleting the occurrence retires that suppression. Punctuation replaces only a candidate-supplied trailing space. Ordinary typing and spaces do not silently correct a draft.

Settings → Tutor → Writing aid and the chat's Writing assistance sheet share owner-scoped preferences. Balanced, Faster typing, Strict and Off can be compared, with independent word, notation, spelling and continuation switches. Personalization can be paused or its learned preferences forgotten. Demo profiles default to Balanced with personalization; live owners opt into assistance. Faster typing's earlier suggestions can influence mathematical wording and are labelled experimental.

The local runtime is lazy-loaded and bundled for web/PWA and Android. It receives newly authored draft text, without the tutor's question or transcript. Revisions and the original learner anchor gate each application. Selection changes, account/checkpoint changes, pasted content, queued answers and composition cannot apply stale offers. A touch holds the original displayed proposal even if a slot changes before release. Typed words can complete one at a time within a bounded acceptance chain; they do not become new learner-authored evidence.

The local contextual ranker learns from ten bounded feedback channels. Explicit accept, refresh and undo carry more weight than passive divergence. It ranks eligible proposals after the existing guards; it cannot invent a proof step. Repeated directly typed vocabulary has separate decay and requires a strong typed prefix before use. The three-seed synthetic comparison chose the contextual ranker over static ranking, reward-frequency and a trained rank-4 adapter. That is evidence about this replay, not human speed or formal logical safety.

The earlier fixed-row evidence is retained as a labelled baseline. The side-by-side debug app is a demo for the owner's physical test; production settings, application ID, release signing and deployment workflows remain intact. Ready and production merge are withheld pending that test.
