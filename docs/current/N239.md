### Write and compatibility contracts

Three new migrations follow the existing future-dated chain: `20261218002700_n239_database_integrity.sql`, `20261218002800_n239_mcp_integrity.sql`, and `20261218002900_n239_note_integrity.sql`. They were generated with the Supabase CLI and assigned unpublished versions after their prerequisites. No applied migration or historical learner row is rewritten. Existing-function replacements are limited to `correct_review(jsonb)`, `concepts_command(jsonb)` and `mcp_commit(uuid,text,text,text,jsonb)`. Their existing restricted ACLs survive replacement and have explicit regression assertions. New privileged helpers use an empty search path and narrowly granted execution.

The application and MCP deployment must follow the migrations that provide their new RPCs. Fail-closed behavior is intentional:

- A live note edit must carry the opened version; UI saves also carry the note ID. The adapter never substitutes a newly fetched version for a stale draft.
- A live note create uses a stable operation ID. Exact replay works after project/checkpoint rename, while replay after Undo reports a conflict instead of resurrecting the note. A database insertion failure leaves no note, card, action or receipt.
- An MCP deletion confirmation must include the 64-character token from its preview. A stale token requires another preview and confirmation.
- A review correction uses the current **card** version, not the review ID or a freshly fetched version attached to an old replacement. The new exact reader covers this command resource only; unrelated command-only read gaps from #1793 are not claimed fixed.
- Each distinct `save_progress` observation should receive a fresh `operationId`; an uncertain retry reuses the same ID and payload. Older callers without an ID receive exact-payload deduplication, so intentionally repeated identical observations should adopt the explicit ID.
- An old unversioned card-edit proposal must be prepared again. It is not approved against an unknown target version.
- Backup format version remains 2 with additive `sourceFiles` and `manifest.originals` fields. Original bytes increase backup size. No automatic source-file restore/import UI is introduced by this issue fix.

PR #1857 remains unchanged and held. Its narrow #1816 compensation change overlaps this batch; N239 replaces the two-write creation path with an atomic command and also covers #1805. No competing change is merged automatically.
