## N54.1 — owner change-feed subscription

The live owner session now starts one shared, owner-keyed `changes_since` poller from the authenticated data hook. Polling runs while the document is visible and online, wakes on window focus/reconnection, drains bounded pages, and backs off after transport or malformed-payload failures. The cursor is never shared across accounts or demo mode; sign-out discards the cursor. Late responses from a previous owner do not invalidate or advance the new owner's cursor.

Known journal resources invalidate their specific query families through `src/data/sync/keys.ts`. Unknown future resources and a retention reset invalidate all cached owner queries, so the client does not silently treat a new kind of change as irrelevant. The in-progress review-run queue is deliberately not invalidated mid-session. Unit regressions cover targeted and fallback invalidation, reset, parsing, duplicate subscription, account switching, hidden-tab wakeup and demo no-op.

The browser read uses the existing owner-session RPC `changes_since(p_cursor,p_limit)`; no service-role client, new migration, or optimistic write is introduced. CI validation is still required before Ready.

The change feed is mounted only when the `v6Shell` feature flag is enabled; legacy live screens retain their strictly bounded HTTP endpoints. This is an intentional compatibility boundary, not a test-specific exception. E2E probes of the legacy shell must not see `/rpc/changes_since`.
