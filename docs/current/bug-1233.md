## bug #1233 — service-only account-deletion classification

The capability inventory classified `account_deletion_requests.cleanup_txid` and `cleanup_pid` as `internal`, which is not a defined N40 classification. Shared unit checks therefore stopped at `Invalid classification account_deletion_requests.cleanup_txid` even on unrelated PRs, including N107 #1214.

Both fields are written and consumed only inside the privileged account-deletion cleanup window. Classify them `command-managed`, consistently with their service-controlled lifecycle, without changing storage, grants, or exposing app/MCP write paths. A focused N40 regression requires both fields to be command-managed, inaccessible through ordinary app/MCP paths and excluded from export. That regression fails on the previous `internal` metadata. No migration or production data changes.
