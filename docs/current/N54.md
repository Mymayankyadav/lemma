## N54 owner change feed (in progress; chat-73024#q5n8)

The N54 branch stages public.owner_changes (global cursor, owner, resource, record ID/version, operation, tombstone and timestamp) with owner-SELECT-only RLS. A trigger on the existing transactional action_changes journal projects writes only for tables registered in lemma_undo_tables; this automatically covers future registry additions, avoids extra triggers on every domain table, and serializes each owner's cursor assignments under one advisory lock. The record identifier is TEXT, preserving real UUID, numeric and legacy string primary keys; composite keys use their canonical JSON representation rather than an unsafe cast to UUID. The full-migration regression explicitly injects a non-UUID legacy key and verifies that generic MCP and browser writes both enter the same owner feed. changes_since is bounded to 100 rows, returns ordered owner-visible deltas, nextCursor and a reset marker, including for cursor zero when prior history was pruned. A service-only 30-day prune function maintains the last-pruned owner watermark transactionally; the scheduled notify tick integration remains to be verified. Isolated full-migration PGlite tests cover journal lifecycle, owner separation, paging, tombstones and reset. **This branch is unfinished, not deployed or review-ready.**

Regression updates: explicit browser-role write revokes for both new tables; replay of the identical study operation appends no duplicate delta, visible same-owner cursors increase, and authenticated callers cannot invoke service-only pruning. Scheduled invocation by the notify tick remains unimplemented, so this PR is not Ready and must not deploy.

Full-migration retention/regression follow-up: a synthetic future owner table contributes no delta while absent from lemma_undo_tables, then contributes exactly once when registered without installing new triggers; service-only pruning is idempotent, non-expired deltas survive, and another owner cannot see the retention watermark or receive a false reset. The 30-day scheduled notify tick integration still needs the Owner-authorized N54 scope correction tracked in bug #1147.

New regression hardening (v2.7): the isolated full-migration PGlite fixture now emulates Supabase's default INSERT/UPDATE/DELETE/TRUNCATE table grants to anon/authenticated before applying migrations, then verifies that **both** new owner-change tables revoke **all four** permissions for both roles. A direct authenticated delta-injection attempt is refused; normal owner-scoped change reads and the service-only retention/migration tests remain. Scheduling the 30-day retention job still awaits the Owner scope decision in #1147, so this PR remains not Ready.

Bounded retention hardening (chat-68290#f2q8): the service-only prune now visits at most eight owners and 500 expired rows per owner per tick, under the existing advisory lock, and advances each owner reset watermark only for rows actually deleted. The full-migration regression inserts 550 expired feed rows and proves incremental 500/50/0 draining without delaying the notify tick indefinitely. **Not Ready:** bug #1147 remains open; notify tick wiring is still outside N54 Scope. Do not merge this PR until Owner authorizes the missing caller/test or introduces its prerequisite.

Multi-owner retention regression: add nine independently expired owner feeds and assert one service tick prunes at most eight owners, the next drains the ninth, subsequent calls are no-ops, and all nine owner reset watermarks remain separate. This is SQL-only hardening; the missing authorized notify tick caller is still blocked by #1147 and the PR remains Not Ready.

Inverse-feed regression: create an owner task through the audited app command, then undo the action and verify that `changes_since` appends exactly one later tombstone for the same record ID, owner-visible row is removed and a second owner sees neither event. This tests that undo's distinct journal transaction emits a replayable change instead of silently invalidating the cursor; scheduled notify invocation remains outside authorized N54 Scope (#1147).

Rollback atomicity test: a study command executed inside a deliberately rolled-back transaction must leave neither a study row nor an owner change cursor; retrying the same operation ID after rollback performs the first real commit and emits exactly one change. The required notify scheduler hook remains blocked by Owner scope issue #1147, so N54 stays Not Ready.

Owner-authorized retention tick (#1147): `runNotifyTick` now invokes a bounded `pruneOwnerChanges` hook once before owner enumeration, even if nobody has notifications enabled. The exported `createOwnerChangesPruner(service)` binds the hook to the service-role-only `lemma_prune_owner_changes()` RPC with no owner identifier, validates the SQL maximum of 8 owners × 500 expired deltas (4,000), respects cancellation, and isolates failed pruning from ordinary notifications. `tests/unit/notify/change-prune-tick.test.ts` verifies the single RPC, empty notification population, bounded output, failures and pre-abort. The Edge scheduler must supply this service-role adapter; browser clients may not invoke pruning.
