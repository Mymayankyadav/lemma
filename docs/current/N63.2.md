## N63.2 Proposal drafts: persistent demo and live owner adapter (chat-82641#k8q3)

The isolated sessionStorage demo adapter provides owner-safe source fixtures, clone-on-read lifecycle, newer-draft protection, strict full-payload JSON, stable per-filter 1–50 keyset cursors, exact counts and version-conflict details. Source drift blocks submit. It never creates an approved proposal.

The live facade uses the signed-in Supabase client and N49 proposal_drafts_command exclusively: owner-RLS reads, exact count plus bounded UUID keyset pages, 1–50 limits, filter-bound cursors, stable operationId for uncertain transport retries, positive optimistic expectedVersion for save/submit/discard, and typed stale/source conflicts with current, base and attempted payload. It resolves the target resource under owner RLS and translates the N63.1 proposal/target base versions into N49's nested projects/notes/checkpoints expected-version snapshot. Create and submit also compare current source versions, while the server rechecks both under its transaction; no owner field is ever passed by the browser. Submit only creates a pending revised proposal through N49 and never performs approval. Test fakes check envelopes, retry, lifecycle, source drift, >50 rows, filters and demo reload. CI must verify the current commit.
