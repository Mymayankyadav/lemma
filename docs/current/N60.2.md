## N60.2 persistent demo day plans (work in progress; chat-73024#q5n8)

N60.2 claims the existing typed N60.1 DayPlanApi. The initial implementation adds tab-local sessionStorage-backed owner-date plans, 1–50 keyset pagination, versioned edits, explicit placed/unplaced/carried-over items, source snapshot validation at preview and commit, and per-date close/reopen with a future-date guard. The demo checks task and calendar block versions against the persistent demo adapters, and new isolated Vitest coverage checks reloads, version conflicts, plan uniqueness, source drift, item dispositions and cursor boundaries.

The index facade switches demo/live by the existing mode. The live adapter uses owner-RLS reads and N46.2 day_plans_command mutation receipts with exact operation IDs, uncertain-outcome retries, and readback checks. CI and review will determine readiness.

Live owner-RLS adapter now uses the existing audited N46.2 RPC for all six lifecycle mutations with bounded server queries, source snapshot validation, receipt/readback parity and stable retry envelopes. The demo now invalidates old previews on update and rejects candidate items absent from their source snapshot, matching N46.2. Live regression tests and CI are still required before Ready.

Additional corrections: demo pagination fixtures now include all 52 item task IDs in their captured source versions; the negative empty-snapshot regression remains. Demo preview edits reset status, clear old item rows and invalidate source snapshots. Live close with a supplied ritual passes only the strict NewDayPlan fields to validation, avoiding rejection of read-only server metadata. Regression tests cover that audited RPC path. These changes have not been declared Ready.
