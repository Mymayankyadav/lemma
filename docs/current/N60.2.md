## N60.2 persistent day plans and owner-RLS commands

The shared N60.1 DayPlanApi now has a selected mode-aware getDayPlanApi()/setDayPlanApiForTests facade. Demo snapshots live in an isolated sessionStorage key and preserve individual civil days, separate closure rituals, previewed placed/unplaced/carried-over items, exact-total filter-bound keyset pagination and optimistic versions. Preview captures source versions; demo commit re-reads current task and block versions and refuses stale sources.

The live adapter reads day_plans/day_plan_items through signed-in owner RLS, never takes an owner field and never directly writes either table. Its six mutations each call the existing N46.2 day_plans_command once, including expected versions for existing plans, and reuse operation IDs on uncertain retry. The command itself locks and rechecks every preview source version during commit, owns action receipts and app/MCP parity, sets a closure instant only on the chosen plan, and clears it on reopen. The browser does not claim to commit placements by itself or treat a preview as completed study time.

Tests: tests/unit/day-plans/demo.test.ts and tests/unit/day-plans/live.test.ts plus unchanged N60.1 model tests. CI verification pending; no production database migration or direct table write was introduced.
