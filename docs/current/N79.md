## N79 settings editors and persistence (chat-85416#n4t8, WIP)

Resumed expired PR #1131. The existing Focus editor now has a sibling Planning editor with validated owner-local HH:MM window, gaps, maximum consecutive study time, daily minimum/intention, start-of-week and 12/24-hour controls. Focus covers timer mode/durations, review budget and attention prompts. Both use the existing updateSettings mutation; no new server endpoint, flag default, or migration is needed.

Live get/bootstrap/update maps N39's typed `focus_defaults`, `planning`, `review_budget`, `attention`, `week_start` and `clock_24h` columns; explicitly maps clock24h to clock_24h on writes. N39's SQL merge trigger preserves unknown nested JSON keys. Demo now accepts the same owner patch keys, validates N39 ranges and recursively retains unknown keys. Isolated regressions cover typed validation, demo preservation and new keyboard-accessible Settings links.

Owner-approved bug #1166 added the narrow Calendar preference scope. The v6 Calendar now respects saved Sunday/Monday week start in Week and Month ranges and 12/24-hour display in saved, blocked and Week labels. Its mode-aware `getApi().getSettings()` read refreshes on window focus, defaults safely when preferences are unavailable and shows a nonblocking warning rather than preventing Calendar interactions. The existing standalone Calendar routes do not require a React Query provider. CI verification follows the latest N79 branch head.

Owner Calendar preferences are read from the mode-aware owner Settings API: the selected week start controls the visible week and month ranges; owner clock preference controls saved/blocked times and the Week grid. Unset preferences fall back to Monday and 24-hour format. N79 unit tests cover Sunday/Monday and clock format.
