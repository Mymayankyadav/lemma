## N183 Activation accepts a diagnostics stream in `action`

The cutover release step on production (2026-11-18, 149 attempt events) found the attempt stream beats its baseline (D1) but fails calibration (D2: slope 0.68, intercept 0.31, ECE 0.14), so its status is `action` with `recalibrating`: serving applies the Platt layer (`serve()` in `_shared/adaptive/fit.ts`, 01 §9). The N175 activation check required `ok` for any stream with 50 or more events, which is stricter than 07 Acceptance 3 ("D1–D5 are reported for every stream that has ≥ 50 events") and I13 (each failure changes serving), so the production cutover could never activate.

`20261218000800_n183_atlas_release_diagnostics.sql` replaces `atlas_check_release_report(uuid,jsonb)` (same signature, security and grants). For a stream with 50 or more events it accepts:
- `ok`, refused if its reported tests contain a failure;
- `action`, only with `tests` holding D1–D5 (each a boolean or null), at least one failed test, and a non-empty `actions` list naming the serving change.

Everything else is unchanged: the 16 numeric gates and thresholds, parity, no Beta imports, exactly four streams with integer counts, `insufficient data` below 50 events, and the applied-conversion check. `scripts/atlas/release.mts` now writes each stream's `tests` and `actions` into the report.
