## N83 v6 durable Review start, run and Done (chat-62804#p9h6)

Under the existing off-by-default `v6Shell` feature flag, Review creates or resumes a durable review run. The live path uses owner-RLS SELECT of `review_runs` and paginated `review_run_items`, validates the pinned settings version, and invokes N62 `review_runs_command` for start, pause, resume and advance. The transactionally committed existing grade RPC returns `reviewId`, which is saved in tab session storage before `advance` and retried without repeating the grade after a lost acknowledgement. Changed/missing cards are explicitly skipped with a reason rather than silently dropped. Progress and Done counts come from the persisted server positions and graded/stale items, not the old transient queue. Next arrivals come from the existing forecast API, with unavailable data not invented.

The demo adapter stores its runs in a separate tab-local sessionStorage key with version checks, preserved graded/stale item states, and independent resume. Focus and keyboard controls remain native buttons; legacy Review/Run/Done render unchanged while the flag is off. Tests cover correct durable totals, reload and stale behavior, receipt persistence and refusal to grade twice. Browser and full CI verification are still required before this PR should be considered deployable.

- Flagged routing preserves a pre-existing legacy/local review round when it has no durable run ID; previously tested reminder-driven Done behavior is unchanged. Live N62 start only accepts UUID card references, so unsupported non-UUID local fixtures continue through the legacy queue rather than being submitted to the owner RPC. Explicit durable run IDs always select the new persistent v6 renderer.
