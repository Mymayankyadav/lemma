## N246 Exam tags and exact evidence links

A `save_progress` event can include `exam:{sitting,row,delivery_ref}`. The database checks that the sitting belongs to the same owner and project and the key is in the blueprint. The evidence carries `mode:'exam'`, `sittingId`, `rowKey` and `deliveryRef`. A matching exam attempt links to the observation whether the attempt or evidence arrives first. A checkpoint demonstration from an exam event requires `exam.criterion_met:true`.

For Atlas-v3 owners the usual typed attempt is still written. The validated exam evidence also remains available to the exam planner and history. New ordinary graded session events receive the Study label and existing unlabeled records keep their previous presentation. The checkpoint Evidence and session history use active corrected events and distinguish independent work, assistance and reading. Ungraded exam recaps keep their mode on the session event without creating an ability observation.

The combined SQL fixture exercises owner and project validation, timer metadata without scoring, and linkage before and after the Atlas cutover. The existing save-progress legacy differential harness continues to cover ordinary payload behavior.
