## N238 Maths typeahead expansion

PR #1861 continues the two handoff commits at `1444b245593b7d0bc372e3351025a26dfeead3a6`. The supplied
[plan](../implementation/typeahead-expansion.html) records the target sizes, budgets and comparative evidence.
The currently shipped trigram is a fallback. New browser behavior is behind the existing default-off
`typeaheadV2`, `tutorAnswerAids` and `proofAssistGhost` flags. A manifest must qualify each neural execution tier
before the app fetches and enables it.

### Browser replay

Run `npx playwright test tests/e2e/n238-typeahead-replay.spec.ts --workers=1` for the synthetic composer regression.
For a consented replay, set `LEMMA_TYPEAHEAD_REPLAY_INPUT` to JSONL rows with `eventId`, `answerId`, `prefix`,
optional exact `target` insertion and optional local Tutor `route`. Set `LEMMA_TYPEAHEAD_REPLAY_OUTPUT` to a local
path prefix for the impressions and key-count files. Supply `LEMMA_TYPEAHEAD_REPLAY_ANSWERS` separately with complete
`{answerId, answer, route?, question?, subject?, aid?}` records for full-answer key counts. The key driver starts from an empty editor and actually
types each character or taps an exact visible suggestion. It checks the resulting draft after every action. The browser obtains the slate and optional ghost
text from the visible UI. The optional question, subject and aids are served from a local Tutor fixture. The answer
enters only the driver, which chooses a tap after the UI displays the slate. Set `LEMMA_TYPEAHEAD_REPLAY_ARM` to
`corrected-v1`, `expanded-kn`, `neural`, `tutor` or `personal`. All five arms use the same insertion guard and menu.
Each result records the active prose, subject, LaTeX and neural model fingerprints. A fixed-caret or trajectory
observation without a prose fingerprint is recorded as empty, ineligible, or eligible with no current model.
Set `LEMMA_TYPEAHEAD_REPLAY_EXPECTED_SUBJECT_SHA_JSON` to an object mapping exercised subject slugs to their
expected pack hashes. The driver checks the active subject against the frozen answer's fixture and verifies
the expected pack on model-backed edits. Set `LEMMA_TYPEAHEAD_REPLAY_GRAPH_TRIAL=1` separately to try a
parity-checked graph that has yet to meet production gates. Unqualified graph trial rows carry an explicit marker.
For a frozen candidate comparison also set `LEMMA_TYPEAHEAD_REPLAY_STRICT_GRAPH_TRIAL=1` and pin the expected bundle
fingerprint. Strict trial keeps the actual backend's cold-transfer cap, excludes software WebGPU adapters and
uses the ordinary deadline. An arm with no on-time scored graph replies is recorded as a fallback observation.
`LEMMA_TYPEAHEAD_REPLAY_EXPECTED_NGRAM_SHA` verifies readiness on an unrelated short warm-up and rejects a changed
fingerprint during scoring. The n-gram manifest must be present before the Vite build so it is compiled into the asset
map. The driver writes partial slates, component records and completed answer costs as they are observed. Only a successful run emits the
separate complete outputs. Missing aligned component samples are recorded as null and unsupported outcomes retain zero. Keep gold event records and private
replay text outside the repository. Run the Python aggregator against the same frozen events for every arm.

The fixed-caret pass disables local learning. The full-answer pass starts with a fresh browser profile and then preserves only
observations from prior answers in its own arm. Calibration needs a separate observed outcome set. Keep the public diagnostic
component log out of the fitting input when comparing those same answers. The report
keeps this idealized result separate from observed noticing, reading and retention in ordinary use.

The current-sized, development and full-pool controls hold the primary model, context length and 100 million
scored targets fixed. The capacity comparison holds the full pool, context length and target exposure fixed.
The role-adaptation comparison measures the combined effect of additional reply-masked training from the same
primary checkpoint. Isolating the effect of the mask would require a matched additional general-training arm.
Report browser weight contrasts only where both graphs delivered on-time scores and backed visible edits.

### Browser and model budgets

The native weight-only int8 pilot used a 34,587,365-byte bundle including the manifest and agreed with the float top-three set in 297 of
300 held-out validation contexts. Chromium's normal WebGPU request returned no adapter. Forcing software WebGPU selected
Google SwiftShader, and the local UI Q/A probe returned zero usable neural scores by the deadline in both WASM and software
WebGPU. The WebGPU runtime introduced a 24,254,953-byte JSEP WASM download, separate from the 13,479,978-byte existing ink
WASM. These results leave accelerated hardware latency, peak memory and ghost quality unqualified.

The int4 pilot used 19,644,707 bytes and matched the float top-three set in 251 of 300 prefills and 205 of
240 cached transitions. The best mixed int4/int8 pilot used 24,215,340 bytes and matched 273 of 300 prefills and
218 of 240 cached transitions. Both failed the export parity gate. The int8 bundle remains a developer diagnostic.
[Int4 evidence](../../scripts/typeahead/expanded/evidence/primary-int4-validation.json) ·
[Mixed precision evidence](../../scripts/typeahead/expanded/evidence/primary-mixed-precision-validation.json).

The initial public corrected-trigram browser run used 24 held-out mathematics answers and their source questions. It logged
66 exact boundary hits in 283 fixed events and saved 584 of 1,859 full-answer key equivalents. The earlier menu filled
otherwise-empty slots with another family member. Comparative replay of the updated models uses strict family
deduplication before a causal comparison. [Diagnostic aggregate](../implementation/typeahead-evidence/corrected-v1-diagnostic.json).


The matched-size CPU diagnostic selected the count-pruned fifth-order n-gram at perplexity 102.195 on 155,670 validation
targets, compared with 102.426 at fourth order and 107.315 at third order with the same 51,815-token vocabulary.
These runs used about 8.39 million training tokens. Two subject packs and one LaTeX pack were available for local browser
ablation. This checkpoint keeps pilot model binaries in the experimental workspace pending the larger-corpus and product
gates.


Local retention uses resolved observations of an accepted insertion over three seconds. A user edit that removes the
insertion within the window counts as a failed retention. A hidden document, account or turn change, unmount, and another
acceptance before the observation completes censor the prior event. Those cases stay outside the retention denominator.


Production neural admission charges the chosen cold runtime download and reserves the general n-gram, one subject pack,
and equation/metadata allowance within a 29 MiB support reserve on ONNX Runtime Web 1.27.0. Browsers with WebAssembly JSPI can select the ONNX Runtime JSPI WebGPU build with explicit
device qualification. Its 15,046,878-byte runtime is 9,208,075 bytes smaller than the Asyncify build. Opening one qualified
neural tier attempts only that backend. A failed load falls back to n-gram without a second cold neural download.

### Fitting and promotion

Freeze corpus-deduplicated calibration, validation and final test schedules before reading the outcomes.
Use the audited group mapping and exclude every inspected diagnostic group. Run calibration and validation
fixed-caret passes with `LEMMA_TYPEAHEAD_REPLAY_CAPTURE_ONLY=1`, `expanded-kn` and the same verified general,
subject and lexicon assets. Keep the input schedules, outcome data and raw capture files in the working area.
The component capture queries the exact target only after capturing the slate. It records actual component
and active fallback probabilities, the document group, and general and subject pack identities.
Replay routing derives the subject from the visible question alone. The corpus's broader subject label is used
for corpus coverage and cannot provide context from the answer.

The mixture fitter shrinks subject coefficients toward pooled coefficients and requires lower supported-literal
mean log loss on disjoint validation against the captured fallback. It records zero support, missing capture
and component availability separately. Those events remain in product replay denominators. The frozen fit
estimates general, subject, question and draft weights. The existing local personal cache retains its separate
weight in the live arm. Package a validated `mixture.json` alongside the matched `ngram-v2` manifest before
building the browser. A different active general or subject pack uses the fallback.

For neural exact calibration use the dev-only graph trial and `LEMMA_TYPEAHEAD_REPLAY_GHOST_CALIBRATION=1`.
Set `LEMMA_TYPEAHEAD_REPLAY_EXPECTED_NEURAL_FINGERPRINT` to the prefill, incremental, tokenizer and external weights
SHA-256 values joined with colons, using `-` when weights are internal. This pass records on-time, guard-eligible,
unshown proposals and an opportunity count. The driver labels literal prefix matches against the remaining answer
only after the actual slate is captured. If a later step delays the complete worker reply past 60 ms, coverage
excludes all its candidates, even those computed earlier. The fitter accepts those rows as exact evidence only. Acceptance and
conditional retention require observed human events with measured exposure. Without those rows, a neural ghost
cannot clear the operating point and utility gate. A fitted artifact is included as `calibration` in the verified
neural manifest for that exact bundle. Re-run release arms on the untouched final schedule with the frozen validated
artifacts to assess product quality and coverage. The audited inputs and consented behavioral observations are pending.
