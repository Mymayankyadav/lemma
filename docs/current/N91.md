## N91 History correction schema and parameter snapshots (in progress)

The branch adds additive correction metadata on `session_events`, a reference to immutable owner-scoped FSRS parameter snapshots on `reviews`, and a new `review_parameter_sets` table. Legacy timestamps read as `coalesce(occurred_at, created_at)`; historical grades with no recorded settings remain explicitly unknown rather than guessing current weights. Owner RLS and explicit browser DML revocations close unaudited writes; new parameter rows have action journaling and generic undo registry membership. A full-migration PGlite test asserts schema, owner isolation, grants and registry. Owner-checked `correct_session_event`/`void_session_event` operations create a linked immutable replacement or a void marker and re-derive checkpoint evidence state from nonvoided, nonsuperseded events in effective event-time order. `correct_review`/`void_review` use a **disclosed complete replacement schedule**, because legacy review logs do not contain the FSRS parameters required for deterministic replay. The supplied replacement and correction rationale are retained in an owner-scoped `review_parameter_sets` snapshot linked from the corrected review. Both operation families use stable operationId receipts, journal their changes and are registered for service-role MCP dispatch. The expanded full-migration regression covers owner separation, exact replay, re-derivation, review state, parameter snapshots and undo. CI and independent production SQL review are required before merge.

Correction and void of ordinary note events now preserve independently recorded checkpoint status and step. Re-derivation runs only if the old or replacement kind is evidence/recheck, covered by full-migration regressions.
