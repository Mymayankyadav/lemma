## N261 Dark-mode UI audit across mobile-up devices

Owner task (2026-11-27): a UI audit of the app in Night, with motion keyframes and stats, interaction and hover states, the pink boundary, mismatched rails and a dark mode that looks washed out; every screen path including the creation drawers, on mobile devices and iPad in both orientations. Follow-ups: upload the scripts and a zip of the images to the PR; make the script traverse every path and screen however small, include the keyboard and its states, cover mobile and up; do not mark the PR ready.

**What exists now.** Nothing in `src/` changed. This PR adds:

- `scripts/ui-audit-2026-11-27/`: the audit tooling. `README.md` lists every script, its arguments and its output.
  - `coverage.mjs` is a static gate: it reads the route table and the enumerated modes (settings sections, Calendar views, Progress and Inbox tabs, demo profiles) from `src/` and exits 1 when one has no scene in `catalog.mjs`. It passes today (29 route patterns, 172 scenes).
  - `catalog.mjs` lists the scenes. `capture.mjs` screenshots them and measures each page. `sweep.mjs` clicks every distinct control of every page and crawls the routes it reaches, to find screens the catalogue lacks. `keyboard.mjs` covers the tutor keyboard (every layer and key state), the Pad's maths keyboard and the hardware keyboard. `motion.mjs`, `strips.py` and `states.mjs` record motion keyframes, hover, press and focus states.
  - `lib.mjs` defines 15 device sizes from 320 × 568 up to 1440 × 900, chosen to straddle every breakpoint in `src`.
- `docs/v7/ui-audit-2026-11-27.md`: the findings, with measurements and the exact scene or script that shows each one. `docs/v7/ui-audit-2026-11-27/` holds the images (two zips of 1× WebP, 77 MB, with a README) and the data JSON.

**What the audit measured, in short.** The pink boundary is the focus ring on the page heading: `useRouteReadingFocus` focuses the `h1`, and `kit-system.css` draws `[tabindex]:focus-visible` in `--v7-role-focus-ring` with a gap. Dark mode is not low in text contrast (median 8–9:1) but in surface separation: the page is `#262624`, cards `#30302E` (1.15:1), card borders `#3D3D3A` (1.21:1), and the graph-paper lines use that same border token. Motion has hard cuts for most state changes and a blank loading frame on the first visit to a route. See the report for the rest and for the proposed token set, which was previewed as injected CSS only.

**Limits.** Chromium emulates the devices; it is not WebKit. The ten added device sizes were captured with the `core` set (one scene per route plus the drawers), not the full catalogue; the sweep ran on 11 pages of three sizes. No defect was fixed and none was filed as an issue.
