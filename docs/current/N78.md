## N78 v6 Practice screen and owner-scoped topic actions (chat-21963#n6w4)

The N78 build adds an opt-in lazy /practice destination only when v6Shell is enabled. The page uses the existing N57.2 mode-aware PracticeTopicApi, never the card-review API, to list owner topics in due-date order with archived topics disclosed separately, read full practice-event history for a selected topic, and record a rated practice (1–4, optional response and minutes) against the current optimistic topic version. The API's committed cadence and date advance are authoritative: the page reloads the owner topic and events after each command, never inventing a due date or completion receipt. The same screen edits validated fixed-day or per-rating cadence, archives/restores topics, and voids an exact historical practice event with its event version. Strict whole-minute, bounded-day and rating input validation displays accessible errors instead of invoking a failing server mutation. All owner reads traverse bounded 50-row exact-total pages with cycle rejection. A new seven-case React regression exercises due ordering, archive disclosure, due-independent practice, rating/response/minutes, optimistic cadence/archive/restore, event void, invalid inputs, >50 pages and the v6-only route guard.

The existing production practice_topics_command and its RLS/journal/undo path are reused without changes. Nothing writes a card review, and the flag-off app has no /practice route. No new dependencies, migrations or unrelated screen changes. CI validation required before Ready/merge.
