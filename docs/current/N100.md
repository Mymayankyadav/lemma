## N100 — v6 learning-screen hardening

The flagged Cards view bounds server pagination: malformed, repeated, regressing and empty-page cursors stop rather than loop. A failed next-page request leaves the displayed cards unchanged and exposes a retry. Existing owner-scoped API reads and incremental 20-card reveal stay intact.

The Atlas hierarchy is now a focusable keyboard-scrollable region; its title and actions wrap at narrow widths and 200% text. Cards search, Paths metadata, plan rationale, conflict payloads, project source disclosure and Inbox selection names contain long content without widening the page. Review grades use a two-column layout on phones to preserve button hit targets. These are v6-only changes; the legacy routes, data adapters and Supabase migrations are untouched.

`tests/e2e/v6-harden-learning.spec.ts` exercises Day/Night at 320/360/390 widths, 200% text, keyboard controls, checkpoint and tutor evidence navigation, more than 2,000 cards via the stress adapter, 30 sources and 1,200 pages, Inbox decision-bar clearance, plan comparison and durable Review reload. Browser assertions cover document overflow and key 44px targets.

Intentional limits: real two-tab live-account concurrency, the 30,000-card extreme fixture, OS Back gestures, accessibility usability sessions and exact-pixel capture remain for N101 and the Owner's physical-device audit. No unsupported browser mutations or flag-off changes are introduced.
