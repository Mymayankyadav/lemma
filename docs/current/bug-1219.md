## Bug #1219 — missing account-deletion release step

Source-level reproduction: N103 introduces `supabase/functions/account-delete/index.ts`
but the existing Supabase workflow only deployed `mcp`. The Settings control
would call an unavailable function on a fresh deployment.

The owner-setup rules change adds a conditional deploy step after successful
migration application and before the existing MCP smoke. The step does nothing
while N103 is unmerged; once reviewed N103 code reaches main, it deploys the
function in the same serialized, credential-gated release path. A deployment
failure fails the job rather than reporting a successful release.

The legacy JWT gateway check is disabled **for this function only** because the
N103 handler validates the bearer using Supabase Auth's `getUser(token)` before
deriving the target owner ID. This must remain true in the final reviewed N103
implementation. No service-role secret is sent to the browser, and this PR does
not deploy or invoke account deletion.

Regression: `tests/unit/ci/account-delete-deploy.test.ts` asserts the guarded
command, ordering and preserved MCP smoke. CI must validate the patch; actual
production deployment requires N103's merge and configured deploy credentials.
