## N157 Everything left in the v7 UX audit r3 checklist, in one PR (13 Nov 2026)

The Owner: "Now you're the only agent working on the task so whatever is left you have to do it", then "merge the result
in one pr … push it repo branch". This one PR carries the rest of `docs/v7/ux-audit-2026-11-12/CHECKLIST.md`. Each part
below names its checklist lines.

### Android icons and names (IC4, IC6, AW14, AW15, AW16; G1's themed ∎; Owner decision E23)

- **One recipe for every launcher shortcut** (`scripts/android-icons.mjs`):
  - the selection tint (`lemma_tint`, from `selection.subtle`) with the glyph in its indigo (`lemma_tint_ink`, from
    `selection.fg`), as selected items look in the app;
  - adaptive on Android 8+ and a round tile on 7.1;
  - drawn from the same lucide glyphs the app shows: Review (Layers), Quick focus (Timer), Capture (Plus), Inbox
    (Inbox) and Resume *path* (Route, never the Atlas star).
- **Old icons:** the three PNGs copied from the web (`drawable-nodpi`) are gone. Inbox no longer uses the file named
  "approve" (AW16).
- **Review:** the dynamic "Review *n*" now replaces the static Review instead of repeating it. Review is always a dynamic
  shortcut ("Review", or "Review 12" when cards are due), next to the three static ones. `Shortcuts.java` allows two
  dynamic shortcuts next to three static.
- **Quick Settings tiles:** each has its own monochrome glyph, a timer for Focus and a plus for Capture. Before, both
  showed the ℓ.
- **Themed icon (Android 13+):** the ℓ and the ∎, both inside the launcher's 66 dp safe circle (the `themed` layout in
  `lemma-mark.mjs`). The grid and margin were already in the background layer (N137).
- **AW15:** one word for a planned block, the app's own ("New time block"). The notification channel and its Settings
  switch are now "Time blocks", as the plan asked ("rename the channel to match the app's word"). Two expectations that
  pinned "Study blocks" changed with it.
- **Check:** the Owner's device checks 6 and 9 (long-press the icon, Quick Settings, the themed icon on a dark
  wallpaper) look at these on a phone.

### AN3 and AN1 leftovers (the sync light, edges, AW3 second stage, AW17)

- **The header ℓ is the sync light** (`src/ui/v7/SyncMark.tsx`, on Today's date line):
  - steady when everything on screen is the server's;
  - a ring while Lemma is fetching or saving, shown after 300 ms so a quick refresh does not flicker;
  - hollow when the device is offline. Only going offline is announced ("Offline: working from your notebook"). With
    N151's "as of" chips this completes "Offline made visible".
- **Edges** (`src/ui/v7/edges.ts`): no Lemma gesture starts within 24 dp of the left or right edge, where Android's back
  gesture starts. This covers the Inbox swipe, the review card swipe, the task row swipe, and the calendar block drag
  and day swipe. A press there still taps.
- **AW3 second stage (E15):** once a day the app asks GitHub's public releases feed for the latest release
  (`checkForUpdate` in `src/platform/device.ts`). The result stays on the phone. When a newer APK exists, the Settings
  icon gets a dot and About this app says "Lemma 2.0.N is available". The privacy page has a paragraph on it, and the
  website never makes the request.
- **AW17:** when the sign-in tab closes and no callback arrives within 1.5 s, the app says that sign-in did not come
  back. If it happens every time, the app's address still has to be added on the server, and the website works
  meanwhile. Before, nothing happened. The Owner's device check 7 confirms it on a phone.

### G1 · the scene camera; A5′ · the release page

- `scripts/v7/scene-camera.mjs` opens a scene of the real app on the example workspace at a fixed clock. It can frame
  the scene (a phone outline and a serif caption on paper) and writes the image. `node scripts/v7/scene-camera.mjs`
  regenerates the install dialog's two screenshots (N133's scenes; `install-shots.mjs` now calls the camera) and the
  Android release image, `docs/release/android-release.png` (1200 × 630 at 2×).
- `scripts/release/android-notes.mjs <build>` writes a release page in plain words: the image, "What changed" (or
  "Fixes and small improvements."), and how to install `Lemma.apk` over the old one.
- **Waits for the Owner:** the Android workflow still writes its one-line notes. Using these notes there
  (`gh release create --notes-file`) changes `.github/workflows/android.yml`, which only an Owner `rules:` PR may do. The
  checklist line stays open with that note.
