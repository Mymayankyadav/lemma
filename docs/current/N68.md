## N68 v6 planner sheet preview selection (WIP · chat-62804#p9h6)

N67's deterministic placement preview is kept unchanged. The new N68 selection module preserves every unplaced task and its reason, turns deliberate deselections into explicit unplaced work, permits a task/part-specific moved interval and rejects overlapping or invalid moves without modifying the source preview. Dedicated unit tests cover these invariants.

This PR is **not Ready**: its native accessible Plan dialog must still be integrated into Today and Calendar behind v6Shell, use owner-scoped task/block/day-plan reads, create selected blocks, use the server's version recheck, keep one undoable receipt, and show a single toast with Undo. No existing flags, data contracts or N67 allocator changed.

The native v6-only PlannerLaunch now opens from Today and Calendar. It loads bounded owner task/block/entry snapshots, runs N67 placement preview, supports deselection and ISO time moves, preserves unplaced reasons, and attempts server-checked day-plan preview/commit after creating task-linked study blocks. It re-reads source versions before writes and compensates created blocks when the first commit fails. A multi-day partial commit cannot be globally atomic through existing separate DayPlanApi and StudyApi commands; the current UI explicitly warns instead of pretending an Undo succeeded. The item remains Not Ready pending an owner-authorized atomic multi-day undo path, a truthful one-toast Undo and full UI regressions.

Follow-up: PlannerLaunch now tracks each split placement by task ID plus part, so deselecting one segment does not silently discard another segment of the same task. The selection module retains the original whole-task input semantics for earlier callers. The dialog close path tolerates jsdom without the native close() method and always unmounts the inactive dialog, preserving Calendar's existing add-block sheet tests.

A takeover guard now revalidates every selected/moved interval immediately before the first block write. It rejects owner-timezone date drift, leaving the chosen day range, midnight-crossing moves and collisions with existing active calendar blocks; cancelled blocks do not block. Pure regressions cover these failures. The outstanding one-toast atomic Undo remains a blocker to declaring the whole N68 item Ready.

Owner follow-up · chat-47863#x6p2: the commit orchestration preflights *every* selected day before the first block write; compares task versions, calendar inventory and saved-focus interval signatures against the preview, and validates moved intervals against all live block/focus spans. A failed later day first invalidates its uncommitted preview (releasing the child FK) and deletes *only* that day's uncommitted blocks; completed earlier days remain untouched and explicitly identified. A lost commit acknowledgement re-reads the day plan before cleanup and never deletes blocks that may already be committed. When only later days contain placements, unplaced reasons are still persisted on the anchor day. These are non-atomic safeguards, **not** a substitute for the Owner's one-toast atomic Undo blocker #1177; the PR is still Not Ready.

Readback ambiguity hardening: if an owner plan's commit response is lost and its authoritative `getPlan` read is unavailable, the app never assumes rollback and never deletes possibly committed blocks. If a preview exists but cannot be invalidated, associated blocks are also retained and identified for owner inspection. The committed/closed acknowledgement path keeps earlier writes intact. New unit cases explicitly simulate all three outcomes. Still blocked by #1177's missing single atomic multi-day Undo.

Stale preview isolation: every load receives a monotonically increasing request epoch. Changing the selected owner day range, closing a native dialog or reopening it invalidates earlier responses so a delayed old fetch cannot overwrite the visible preview or enable a commit using the wrong range. Owner task paging rejects repeated cursors and malformed page sizes early; focused React regressions verify stale read rejection after close/reopen and looping cursors.

Calendar navigation guard: if a mounted PlannerLaunch receives a different owner date or time zone while its native dialog is open, it invalidates the in-flight preview and closes the old dialog instead of leaving an edit surface anchored to a different date. The next open obtains a new owner snapshot. A React unit regression exercises switching Calendar dates without unmounting the planner.

Commit-time selection regression: pairwise overlapping selected intervals are now refused independently of the earlier sheet validation, before any owner calendar block write. This protects against stale/programmatically supplied snapshots. The atomic multi-day Undo blocker #1177 remains unresolved; not Ready.

Unknown creation acknowledgement: when the owner calendar-block create RPC fails before returning its receipt, N68 now explicitly warns that the block may already exist and asks the owner to inspect Calendar before retrying. It never attempts unsafe deletion of the unknown block. Regression simulates a dropped create acknowledgement. Atomic multi-day Undo still needs Owner resolution #1177; not Ready.

Planner move duration invariant: moving a selected placement now preserves its `minutes` allotment. Selection rejects a silently resized start/end interval and the independent commit preflight checks the same invariant, preventing a stale/bypassed UI snapshot from booking longer focus time than the preview showed. Focused regression covers valid relocations and invalid resizes. The multi-day Undo scope gap #1177 remains open; Not Ready.

In-flight planner commit UX: while the owner command sequence is running, disable the dialog's Close button, placement checkbox and move fields, and prevent the native Escape/cancel event from dismissing the sheet. This avoids implying that a durable partial commit can be cancelled or safely edited after dispatch. A focused React test holds the owner preflight read pending to assert all controls, then releases it. The atomic multi-day Undo issue #1177 still prevents Ready.

CI compatibility fix: enforce the existing owner-local date/cross-midnight rejection before the new duration invariant in commit preflight. Invalid day moves retain the original actionable error, while same-day unexpected resizes remain rejected. No test expectations loosened.

Calendar navigation in-flight isolation: after a date/time-zone switch, a previous owner's accepted commit is never advertised as cancelled, but its late success/failure cannot close the new day's dialog or surface the old error. Regression checks both stale failed and successful owner acknowledgements. N107 atomic multi-day receipt/Undo remains a prerequisite before N68 can be Ready.


### Stale commit completion after Calendar navigation

Each Planner commit captures an epoch that is invalidated when Calendar changes the owner day or time zone. A late completion from the previous date cannot reset the new dialog's in-flight state or close a new preview on an A→B→A return. Regression tests exercise overlapping old/new writes and same-day return after navigation. This is a client-state isolation guard, not a substitute for N107's atomic multi-day commit and one truthful Undo; N68 remains Not Ready.

## Owner completion (owner-setup, 2026-11-08): one atomic commit

Per owner decision #1177 the per-block and per-day orchestration and its best-effort cleanup are removed. After the advisory preflight (task versions, calendar and saved-focus snapshot, window, existing plan states), `commitPlannerSelection` makes a single `DayPlanApi.commitPlacements` call (N107) carrying every selected day, its captured task, calendar-block and saved-focus source versions, the placements and the unplaced reasons. A typed server refusal means nothing was written; a transport failure is reported as uncertain and the sheet reuses the same operation ID on retry, so a retry is a replay. The success toast offers Undo (`undoPlacements(actionNo)`) only when the receipt has a journal action; demo has none.
