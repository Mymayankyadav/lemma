## N160 — the Owner's 30-area chat-connector checklist

**Owner task N160** ("Implement these"; the list is in `docs/mcp/OWNER_CHECKLIST.md`). `docs/mcp/capability-map.json` maps each of the 30 areas to the registered resources, operations and tools that serve it, and `tests/unit/mcp/capability-map.test.ts` fails when a named resource, operation or tool does not exist, when a registered resource belongs to no area, or when an unfinished area has no entry in `NEXT.md`. 29 areas are `supported`; area 30 is partly done (below).

Every command below follows the app's rules: owner from the signed-in session (the connector sets it through `mcp_command`), an `operationId` receipt that replays exactly and conflicts on a changed payload, `expectedVersion` conflict checks, and, where the data is journalled, an `actionNo` that `undo` reverses. Each migration is additive only (checked with `scripts/ci/migrations.mjs`).

### Not done, and why

- **Area 30, reminders in the background (N160.10 in `NEXT.md`).** Recurring tasks and scheduled replans run in the database. Reminder notifications are generated and sent by the `notify` code, which has no deployed entry point in this repository, so I could not build or verify their background delivery here. `test_notification` queues a row; whether it is delivered depends on that deployment.
- **No in-app approval for account controls.** The confirmation is the two-call token plus the instruction to wait for the owner's reply; the app does not show a pending approval.
- **No Playwright test for device commands.** The runner, the delivery reports and the SQL are tested; an end-to-end run needs a signed-in live session.
- **No new `selftest.ts` partitions** (the live selftest has a fixed count); the smoke check was extended instead.
- A Time log screen change was not needed: Edit, Split and Void already exist there.
