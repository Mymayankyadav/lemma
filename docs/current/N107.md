## N107 — atomic planner placement commit (in progress)

The first N107 slice defines a strict side-effect-free commit request across 1–31 owner civil dates. Every selected task is tied to its captured version; calendar block and saved-focus snapshots also retain their version. No overlapping new placements, duplicate dates/positions, cross-day starts, missing task snapshot, malformed time zones or unknown owner-controlled fields are accepted. The validator preserves explicit plan versions, unplaced reasons and ISO instants without writing data. Unit tests cover successful multi-day validation and adversarial inputs.

### Atomic SQL batch (N107)
One additive `20261123120000_day_plans_atomic_placements.sql` migration now creates an owner-scoped, receipt-backed internal `lemma_day_plans_atomic_commit` and compatibly replaces `day_plans_command`, retaining the prior implementation of all six existing operations. Phase one validates every requested civil day, owner plan CAS, task/block/saved-focus versions under locks, bounded placements, duplicate source/position and overlap checks. A stale or foreign source or existing occupancy returns a typed conflict before any domain write. Phase two creates linked study calendar blocks, commits new or draft day plans and writes all placed/unplaced plan items in one transaction, with one journal action and exactly replayable receipt. A full-migration PGlite regression checks two-day writes, stale task/block/focus refusal, foreign owner, replay, collision, MCP provenance and whole-action undo. This PR is **not Ready** until the live/demo `DayPlanApi.commitPlacements` adapters are added and CI validates this migration.

### N107 typed live and demo adapters

Added an additive `DayPlanApi.commitPlacements(input)` signature returning one `StudyReceipt<AtomicPlacementResult>` with all committed plans and linked study block IDs. The live adapter validates normalized placement requests, sends one owner-free JSON `day_plans_command.commit_placements` RPC with a stable operationId on uncertain network retries, rejects conflicts and partial/unaudited receipts, and owner-reads all committed plans to verify their versions before returning the single actionNo for undo. Saved-focus version snapshots now round-trip through typed plan availability rather than being silently dropped. Demo preflights every day and all supplied source versions, prevents cross-day/current calendar and saved-focus overlaps, creates linked study blocks before publishing plans/items together, compensates created blocks on failure, and persists exact operationId replay receipts across adapter reload. Demo receipts retain actionNo:null (the pre-existing demo adapters have no journalled undo path); do not claim a server undo from demo mode.

Focused unit tests cover real owner-free RPC envelope mapping, actual multi-resource receipt/readback validation, network retries, stale/partial conflicts, two-day demo persistence/replay and all-or-nothing stale-source refusal. **Not Ready** until CI confirms full SQL/unit/typecheck/e2e and any remaining demo atomicity/undo restrictions are resolved without weakening tests.
