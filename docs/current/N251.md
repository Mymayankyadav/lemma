## N251 Exam mode on by default

Owner: "Turn on exam mode in the app", then "Fix the screens and tests and then create pr". `examMode` in `src/flags.ts` now defaults to true; `?flags=-examMode` turns it off in dev, test and e2e builds. Production now shows everything N241–N243 built behind the flag: "Prepare for an exam…" and the Exam tab on a Path, Today's exam and return cards, the sitting's own tutor conversation, card ideas on the Cards tab, Practice's short topic reviews and the Calendar's exam label. The server side (N240, N242, N244–N246) was already live. N247 recommended keeping the feature opt-in until it had an independent review and observed outcomes; the Owner chose to release it, and the numeric policy still runs only in shadow.

**Screens.** A review of every exam screen in light and dark, at 390 × 844 and 1280 × 860, found these and fixed them:
- **Exam tutor header.** It was a pill holding "Exam prep · title · time to exam · minutes left", three lines tall on a phone. It is now the checkpoint tutor's centred title with one status line ("Exam prep · 2 d 23 h to exam") coloured by phase. The study budget stays on the "I have N min" chip. The button's accessible name is still the whole sentence.
- **Empty exam conversation.** It showed only the sitting's title. It now opens with the tutor's "On the table" card: "Exam prep", the title, one sentence, then Quick check and Read a recap.
- **Text sizes.** Back to study, Finish exam… and I have N min used the large button size beside small ones. All exam controls are now small, in the composer row and in the Exam session sheet.
- **Course tutor banner.** "Exam prep is active for this subject" sat flush against the session parts and "Open exam chat" looked like plain text. It now has the same spacing as the start card, a secondary button and a ghost Dismiss.
- **Coverage conflict.** The sentence from the shared planner ("Compulsory Decide …: 17.0 marks exposed.") was indented as a list. The app now shows "**Decide …** is compulsory · 17 marks exposed", with the planner's number format, and keeps the raw sentence if the wording ever changes. The server text is unchanged.
- **Setup and row sheets.** Goal, Format notes, Card creation, How likely is it to appear?, Back and Concept now have the bold field labels. The exam checkboxes use the app's checkbox, and Exam sources and Checkpoints use the app's chevron instead of the browser's triangle.
- **Ideas and Practice.** An empty Ideas tab explains what will appear there. On Practice, the exam topic reviews use small secondary buttons, so the view keeps one primary (PR2).
- **One primary on Today (PA11).** The countdown card's Prep now and the return card's Continue studying are now secondary, so Today's next-step card keeps the only primary above the fold.
- **Path tabs follow the header (N157).** The return card used to sit between the Path header and its tabs, pushing the tabs 185 px down for up to two weeks after an exam. It now opens the Plan tab. The Study / Exam prep control for a live sitting stays above the tabs, because it switches the whole Path.

**Bug fixed.** `DemoAdapter.getHome` built its exam card through `getExamApi()`, which follows the page's URL mode. Used outside `?demo=` (unit tests, stress fixtures), it reached for the live client and failed with "Lemma Supabase configuration is missing". `getDemoExamApi()` now returns the demo exam store whatever the mode, and `getExamApi()` uses it in demo mode, so the browser demo keeps one store as before.

**Browser specs.** A run of the exam, tutor, Today and Path specs with the flag on found seven failures, all of which pass with `-examMode`. Two were the design rules above (PA11 and N157). The other five came from specs whose mocked server answered only `home_summary`, so Today's first read failed. `tests/e2e/helpers/live-tutor.ts`, `offline-startup`, `live-api-budget`, `fix-517-insights-math`, `v7-scheduling-preference` and the three N195 live specs now answer `exam_home_summary` as the server does. `live-api-budget` still allows Today one summary read: `exam_home_summary` once and `home_summary` never.

**Tests.** 23 unit tests failed with the flag on: 16 from the bug above, and 7 whose mocks knew only `home_summary`. The live mocks now answer `exam_home_summary` (the server's `home_summary` plus `exam`), and the ST-5 test asserts that Today still makes one read. A new test checks that Today falls back to `home_summary` only when the exam-aware function is missing, and makes no second call on any other error. `tests/unit/flags.test.ts` checks the new default and both override directions.
