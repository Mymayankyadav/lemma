## N225 · Atlas MCP-first graph proposals (no model API key)

## Goal and boundaries
ChatGPT or Claude is the reasoning worker. Lemma never stores a provider API key or calls a model from Supabase. The existing, owner-authenticated MCP connection is the only tool surface for reading facts and creating **pending** typed-link proposals. Review, approval, merge, reclassification, and educational evidence remain separate explicit operations.

The first release is an enabling slice, **not** a complete closure of audit X1–X9. It does not backfill the owner's current 535 concepts, and it must not run autonomous approvals.

## Worker contract
1. Call `get(what="atlas_worker",id="concepts",limit=50)` and follow `nextCursor`; repeat for `subjects`, `projects`, `concept_links`, `atlas_links`, `concept_aliases`, `checkpoints` and `checkpoint_concepts`. Every read is bounded and owner-scoped.
2. Prefer changed concept hashes and their mathematical neighbourhood, but make a full scan on first bootstrapping. No model is used to generate candidates in the backend.
3. Examine equivalence, generalization, instance/theme, technique-use, contrast, analogy, and part-of relations. Do not assume a high similarity score proves equality. Distinguish strict prerequisites from one course's proof order.
4. Check existing typed links and aliases before proposing. Use the exact version and `content_hash` returned by MCP reads. Give a concise mathematical rationale (no more than 20 words / 200 characters) and calibrated confidence.
5. To create a pending relationship, call `study` with the ordinary owner-scoped command envelope:
   - `schemaVersion:1`, `resource:"atlas_link_proposals"`, `operation:"create"`
   - a fresh `operationId` UUID; reuse it verbatim on a retry
   - `patch:{from_id,to_id,kind,confidence,rationale,from_hash,to_hash}`
   - no `target`, no `status`, no `origin`, and no approval
6. Inspect the command receipt and re-read `get(what="atlas_links",id="<proposal-uuid>")` or paginated `get(what="atlas_worker",id="atlas_links")`. Pending status is not equivalent to approved model input.
7. Show the owner a bounded review queue (recommended 25–50 per run). Only explicit owner decisions may call `study` with `resource:"atlas_link_proposals"`, `operation:"approve"/"reject"`, `target:{id}`, and the current `expectedVersion`.
8. For assessment, `get(what="atlas_tag_suggestions",id="<concept uuid>")` lists possible prerequisite/technique/part tags. These are advisory; the learner/tutor must confirm actual demands, result, cues and hints in an attempt. Never manufacture evidence.

Use a **weekly** scheduled AI task by default for the current graph; use event-driven or nightly scans only if imports/edits are frequent. A task may be unable to use the connector in unattended mode, or may pause for approval: verify its first run before relying on the schedule. Never store MCP connector secrets in a prompt, repository, or task.

## Model semantics
- Plain `concept_links` remain the Atlas map edges and prerequisite recheck priority.
- Approved typed `atlas_links` supply statistical shared effects for equivalent, generalises and instance_of only. They do not certify mastery or automatically complete prerequisites.
- `concept_aliases` now contribute a single synthetic approved equivalent **ability component** in both MCP and browser calculations, without modifying evidence or adding a visible map edge. If a real approved equivalent link exists for the same pair, do not double count.
- The UI does not yet display all typed links on the star map.
