## bug #1215 — machine-local dependency symlink committed to Git

The clean repository previously tracked a root `node_modules` symlink whose target was an absolute path on a contributor's machine. That entry cannot work on other machines, and an ordinary `npm ci` can mask the problem by replacing the working-tree link.

Remove **only** the tracked symlink from Git. Keep `package-lock.json`, installation, ignore rules and CI configuration unchanged. `tests/unit/repo/tracked-node-modules.test.ts` inspects the committed tree using `git ls-tree HEAD`, so a clean-clone checkout containing the path fails regardless of whether dependencies have been installed. No application behavior or vendor files are modified.
