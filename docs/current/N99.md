## N99 — planning screen hardening

The v6 Tasks backlog now validates owner page shapes and cursor advancement, refuses repeated/empty advancing pages and ignores stale page responses following a refresh. Large backlogs remain paginated (20 rows per request); existing optimistic edits, ordering and version-conflict handling are unchanged.

Calendar Month and Day now keep their wide date/hour grids inside independently keyboard-focusable horizontal scrolling regions instead of widening the viewport at 320px and enlarged text. Week exposes the same keyboard scroll affordance. Deadline disclosures and overlap acknowledgements have 44px minimum hit targets. Ritual headings and saved-work rows, Practice topic/history text and Planner unplaced reasons wrap long mathematical content without requiring horizontal page scrolling.

Browser regression coverage: 55 tasks across three bounded pages and reload; all four Calendar views with a New York DST fall-back day (25 distinct hourly rows), narrow layouts and enlarged text; Planner native Escape/Close; and dated ritual/Practice navigation, empty states and keyboard access.

Remaining intentional constraints: horizontal scrolling within dense seven-column and three-column timetables is preferable to truncating owner data at extreme font sizes. Demo task persistence is scoped to its own browser tab, so this browser suite does not claim live cross-tab consistency or physical-device keyboard audits. No data adapter or production migration is changed.
