## N169 Adaptive core: one time block, evidence-driven rechecks, a daily scheduler (Owner task)

Spec: `docs/spec/adaptive-learning-spec.md`. Plan and decisions: `docs/spec/adaptive-learning-plan.md`. This is PR 1 of 2 (spec Phases 1–3). PR 2 (N170) is proficiency, items, Atlas memory, workers and calibration.

**Everything is behind per-user flags in `settings.flags` and is off by default.** With every flag off the tutor and the app behave exactly as before; each flag is switched on with `edit` on settings (`flags: {recheck_v2: true}`; flags merge, so one never switches another off).

| Flag | What it does |
|---|---|
| `time_block` | `resume` returns OWNER, RULES (≤ 10 lines), TIME, QUEUE, BRIEF, FLAGS (≤ 1500 tokens, tested for all four production-shaped projects). `get(what=time|queue|feasibility|forecast)`. No pace or finish-date number outside `forecast`. |
| `recheck_v2` | Checkpoint completion no longer schedules a recheck (the loop). `save_progress` writes evidence; rechecks are replayed from evidence (T1–T5). WARM, `end_session`'s generic prompt and the `recheck_*` / `needs_revisit` writes stop; `edit`/`add` refuse them. |
| `scheduler_v2` | At `start_session` / `end_session`: freeze today's slack, defer what pruning allows without approval, restore in exact reverse order after 2 consecutive study days above +10%. One notice per run; the whole run is one undoable action. |

### Decisions that differ from, or complete, the spec
- **Rechecks are a replay, not stored facts**: `rechecks` is a cache rebuilt from evidence, misconceptions with a concept, `recheck_decisions` and the plan. Undo or redo of any fact therefore recomputes the exact set (I7, tested as a property over random histories).
- **Deferral** uses `checkpoints.plan_state` (the `status` CHECK cannot change in an additive migration). Until the app has a deferred state it shows a deferred CP as not started.
- **Step tiers** are stored only when explicit (`venture`); other steps inherit their checkpoint's tier, so approving tiers later never leaves a step stale. Venture steps inside a core checkpoint are still prunable (they are optional enrichment); the rest of a core checkpoint never is.
- **Same-deadline projects share capacity in proportion to what they still need**, so a project with no sessions still reserves its share. Earlier deadlines are served first; explicit `share_weight` overrides.
- **Prerequisite summary**: pruning a checkpoint that a kept checkpoint depends on defers it with a ~15 min summary step on its first dependent (stored as `deferred_reason = 'prune:standard_cp>CP7'`).
- **QUEUE shows the real plan**: proposed pruning appears in FLAGS and `get(what=feasibility)` and changes the queue only once it is applied (automatically under `scheduler_v2`, or by `edit … plan_state`).
- **Restore is judged on the whole shared plan** and only when nothing at all is being pruned, so it never takes capacity another project needs.
- **12 h abandonment is derived** (an open session idle for 12 h makes no T3 rechecks), never written on a read. `start_session` marks the sessions it interrupts `abandoned` under `recheck_v2`.
- **Evidence defaults** when the tutor gives no tag: the concept is the checkpoint's only concept (confidence 0.7) or stays unresolved and is listed in FLAGS, never invented; level is `recall` for pretests and recall questions, `understand` for explanations, else `use`.
- **Capacity is never guessed**: unset shows `capacity_today=unset` and a FLAGS question. `adaptive_migrate` writes capacity and the last study day only when given them.
- **`pace_factor`** uses the minutes of the sessions on a checkpoint as its actual time (study entries carry no CP minutes). Production shows about 3× today, which is why topology-1 is infeasible.
- **tools/list**: measured 13,510 of 15,000 characters after the new event fields (13,173 before).

### Data migration (not run by this PR)
`select public.adaptive_migrate('{"owner":"<uuid>","dry_run":true,"time":{"last_study_on":"2026-11-22"},"capacity":{"weekday_minutes":240}}')` (service role) returns what a real run would change and rolls back. A real run (`"dry_run":false`) is one journalled action (`undo A<n>` reverts it) and is idempotent. It never edits free text; `get(what=…)` / the FLAGS line list the `prompt`, `goal` and `target_label` values that need a diff proposal. Steps: `snapshot, time, typing, estimates, baselines, recheck_fields, evidence, diagnostics`. Tiers are drafted and written only with `approve_tiers`.
Old recheck fields: every `recheck_due` / `needs_revisit` on a demonstrated checkpoint is retired and a generic `Recheck CPn` prompt is dropped (a concrete prompt is kept for the item layer). A gap fixed during a session is already a T1 trigger in the backfilled evidence, so it is not seeded twice; only an explicit `needs_revisit` (a failed old recheck) seeds one trigger per concept.
