## N194: First path and first card preview

This draft covers the first vertical flow deferred by N189. In development and test builds only, open v7 Review or Cards with the query parameter `demo=first-use`. Unlike a caught-up queue or active search, the panel waits for a successful unfiltered card-library read and a successful path read. It offers a first card in an existing path, or a path and card together. Cancel and reopen to retain the unsent text. The new-path case requires three fields (path, front, back) and two button activations to save; the saved-card detail is verified before offering the existing Review now action. Reveal and grading remain separate.

Fixture storage retains an operation UUID before dispatch and puts the new path/card and matched operation result into one tab-storage snapshot. An exact replay after the tab reloads returns the original IDs; changed payloads conflict, and a failed mandatory storage write rolls the in-memory transaction back. Demo data, run IDs and the first-use draft stay in the preview's tab namespace. Neither the entry UI nor a write endpoint is enabled for live sessions.

A confirmed conflict ends retries for that operation. The learner can recover the path, front, and back after reload and dismiss the draft explicitly. An unknown save outcome keeps its original retry key. The browser regression restores a pending intent after a different card was saved and checks that exactly one card survives recovery.

This is not the live first-use release. A trusted owner-bound transaction, compatible receipt writer authority (see N191 / #1533), separate roles and connection-race fixtures, approval and rollout evidence are still required. A lost grade acknowledgement before the current UI receives the review ID is not solved by this preview; no production-grade guarantee is inferred from the normal explicit grade test.
