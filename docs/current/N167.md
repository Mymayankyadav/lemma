## N167 The Review hub no longer cycles "Loading the forecast…" after a cold start (Owner task, 16 Nov 2026)

Owner task: "This is stuck in loop of loading forcast and showing the above" (screenshot of the Review hub, 0 cards today).

**Cause.** The owner change feed (`src/data/sync`) keeps its cursor in memory, so every cold start reads the owner's whole retained journal from cursor 0 (17,825 rows on the Owner's account), 50 rows per page. Each page invalidated its resources' queries and awaited their refetch before reading the next page, so for several minutes every active screen refetched about every 1.5 s. The Review hub's forecast is keyed on the decks and settings fetch times, so each refetch gave it a new key with no data and it showed "Loading the forecast…" again. Edge logs for 04:36–04:38 UTC on 16 Nov show ~650 requests a minute (`changes_since` ~42/min, `settings` ~74/min, `home_summary` ~43/min).

**Fix.**
- `src/data/sync/index.ts`: while a backlog drains (a full page with more to come), the touched resources and any reset are collected and invalidated once when the drain ends. The pending set lives beside the cursor, so a poller stopped mid-drain hands it to the next one; `clearOwnerChangesCursor` discards both. Steady-state polling is unchanged.
- `src/features/review/v7/ReviewHubV7.tsx`: the forecast query keeps the previous chart as placeholder data while a new key refetches, so a deck or settings refresh no longer blanks it.

**Still true.** A cold start still reads the whole retained journal (now without refetches). Persisting the cursor per owner, or a server call that returns the head cursor, would remove that read; not done here.

Test: `tests/unit/sync/owner-changes.test.ts` "drains a cold-start backlog with one invalidation, not one per page" (fails before the change: decks are invalidated once per page that touches cards).
