## N93 Owner-scoped aliases and source revision snapshots (in progress)

Adds owner-scoped historical slug/code aliases for projects, concepts and checkpoints. `resolve_alias(kind,value,scope?)` recognizes current or prior identifiers and refuses ambiguous codes without subject/project scope. On content updates, owner-scoped source and source-page revisions capture the exact prior JSON snapshot and deterministic hash once per meaningful change. Immutable revisions are not logged as extra source-action changes and survive undo; undo does not manufacture extra history. PGlite migration acceptance covers project rename, old/new resolution, source/page revision uniqueness and cross-owner read isolation. CI v2.7 now permits the required browser DML revokes on newly created tables; the PR still requires final verification and independent production SQL review. Source/page revision tables have owner RLS and capability metadata, but are deliberately not in the generic undo registry because they must retain immutable snapshots and may not inflate legacy source edit audit counts. Their eventual export inclusion requires a separate owner-approved registry/export compatibility decision.
