## N93 Owner-scoped aliases and source revision snapshots (in progress)

Adds owner-scoped historical slug/code aliases for projects, concepts and checkpoints. `resolve_alias(kind,value,scope?)` recognizes current or prior identifiers and refuses ambiguous codes without subject/project scope. On content updates, owner-scoped source and source-page revisions capture the exact prior JSON snapshot and deterministic hash once per meaningful change, including genuine inverse edits during undo. SECURITY DEFINER triggers deliberately do not trust a caller-controlled `lemma.tool='undo'`: authenticated spoofing cannot suppress alias/snapshot history. Revisions are append-only and not logged as extra source-action changes, preserving existing DB-5 action counts. PGlite migration acceptance covers scoped project/concept/checkpoint renames and collisions, prior-content snapshot uniqueness, owner isolation, authenticated spoofed provenance and genuine source-page undo. CI v2.7 now permits the required browser DML revokes on newly created tables; the PR still requires final verification and independent production SQL review. Source/page revision tables have owner RLS and capability metadata, but are deliberately not in the generic undo registry because they must retain immutable snapshots and may not inflate legacy source edit audit counts. Their eventual export inclusion requires a separate owner-approved registry/export compatibility decision.
