## N198 New planning and Lemma Pad release

This candidate is based on main `8d9845f353542b322959f9d00c0a3e3e3ccb4b01` after N191, N192, N193, N195, N196 and N197 and the S0 fix. PR #1733 began at `7817517bea2c6223f51210cfc9c3e460edfe19a9`. Use the PR head and its checks for the revision under review.

### Release behavior

- Build defaults enable the new agenda, full Lemma Pad, live checkpoint tutoring, and first-study and review repairs. The authenticated app and MCP use the same server release decision.
- When the server release is open, an owner with no stored choice uses New. **Settings → Planning → Scheduling algorithm** saves New or Legacy for that owner. Today, MCP queue and resume use the saved choice for future decisions. Existing rounds and review history retain their original decisions.
- Lemma Pad is available from the app menu and from a checkpoint. The custom math keyboard starts visible and can be hidden. Native typing, hardware input, selection, ink, export and explicit tutor submission stay available. The cold offline route avoids the signed-in study release provider, so it can reopen a previously authorized Pad without refreshing a session.
- The offline banner includes its Pad link in the initial bundle. Going offline can show the link without fetching the module over the network.
- The private deployment control starts closed on install and upgrade. Authenticated and service roles can read the boolean. The database operator controls activation and rollback. The browser and MCP share this control. Practice forecast, challenger serving and trial admission retain their independent controls.
- Agenda capacity uses the union of saved focus on the owner's civil day, after subtracting entry-specific drift and the union of saved breaks. [#1726](https://github.com/Mymayankyadav/lemma/issues/1726)

Run the activation transaction from the approved database operator session.

```sql
begin;
insert into public.tutor_release_controls(capability, enabled)
values ('manual', true), ('mcp', true)
on conflict (capability) do update set enabled = excluded.enabled;

set local role service_role;
select public.lemma_practice_controls(true, false, false);
reset role;

insert into lemma_release.plan_control(singleton, enabled) values (true, true)
on conflict (singleton) do update set enabled = excluded.enabled;
commit;
```

### Rollback

Close the shared gate with the database operator.

```sql
update lemma_release.plan_control set enabled = false where singleton;
```

Check the live app and MCP after the gate is closed. Existing receipts remain recoverable through their original command paths. The shared gate blocks new release-only writes while preserving N197's receipt protection, saved owner choices, materialized rounds and Pad revisions. In an already-open app, navigate or refocus online so it rechecks the gate. Rehearse reopening on an isolated account before a new production activation.
