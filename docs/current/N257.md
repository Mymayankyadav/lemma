## Equation paper: read the completed drawing once

With **Draw single symbols** enabled, Equation mode now submits the complete normalized drawing once per committed stroke. It no longer synthesizes UI pen events for all older strokes and sends intermediate revisions that can never be accepted. Undo can re-enable symbol reading after a drawing exceeds the existing 12-stroke symbol limit. The complete drawing is always available for the explicit **Read equation** action. Ink, automatic-insert policy, scores and model files are unchanged.

Opening Equation mode uses one cache-presence check rather than two. The worker examines the pinned model cache's keys, not response bodies, before the existing cached-model preparation. Actual model loading still verifies the bytes. The change does not add prefetches or alter the existing consent dialog.

**Local measurements, not release thresholds:** desktop headless Chromium 153, 393 × 873 touch-sized viewport, no CPU throttling. Production-built Tutor → Write a question → Equation mode, public packaged Detypify; six repetitions of a two-stroke ∀ and one drawing extended to 16 strokes. On the same 28 lifts, model dispatches fell from 53 to 23. From the last lift to the visible ∀ choice, the median over five warm attempts fell from 38 to 30 ms; down to the next animation frame following a live SVG path was about 15 ms both ways. The initial symbol result varied with worker startup; no cold-start speedup is claimed.

Manual whole-equation reads are a separate path. With the real checksum-pinned 118 MB Pix2Text weights installed, one four-stroke sample took about 4 s to visible LaTeX on the cold session and 2.3–2.6 s on warm reads. This patch does not speed up model inference. No production telemetry or real-user ink was collected. No physical iPad, Pencil, Android device or mobile-browser frame timings were tested.
