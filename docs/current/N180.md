## N180 Atlas v3 cutover: the ordered runbook

State on 2026-11-18 (read-only check of production): one owner, 4 active projects, 146 evidence rows, no cards or reviews, `atlas_migrated_at` unset, no attempts, no fit, no conversions. The Atlas v3 migrations of #1501 and #1506 are deployed and dormant. The per-user flags on are `recheck_v2`, `time_block` and `scheduler_v2`; the Beta `proficiency` flag is off, so removing the Beta model changes nothing the owner sees today.

### What must be merged before the cutover (in this order)
1. **This PR (N180):** the release tooling below and the measured simulation gates (`research/sim/results-gates.json`). No review needed.
2. **Beta removal (`rules:` PR, Owner merges):** removes `_shared/adaptive/proficiency.ts` and every import of it (`digest`, `facts`, `items`, `node`), replacing the protected Beta tests. Until it merges, `scripts/atlas/release.mts` reports `no_beta_imports: false` and activation refuses, by design (07 Acceptance 5).
3. **Corrections after cutover (review required):** a new additive migration so that voiding or correcting a session event also voids or supersedes the attempts written from it (today only the frozen evidence follows the event, so a corrected event would keep feeding the model).
4. **`atlasV3` on by default (review required, Owner decision):** after activation the app's current screens read the frozen evidence and stop changing; the Atlas v3 screens read attempts. Merge it right after activation (step 9), not before.

### The cutover (Owner present; one fresh chat for steps 1–2 and 4–8, one per project for step 3)
Every write runs only after the Owner's yes in that chat, one step at a time. Reads and dry runs are free.

### What activation checks (so nothing is skipped)
Owner-approved dry-run hash; migration complete; a version-3 fit; every gate of the report a JSON number within its threshold (`research/sim/gates.py` and the production numbers); exactly four diagnostic streams with integer counts (with 146 events the attempt stream is checked, the others show `insufficient data`); app/MCP parity; no Beta imports; and for every active project an approved conversion that was journalled, not undone, and applied.
