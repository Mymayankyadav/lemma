## N123 Lemma for Android: the Capacitor app (Owner task, one PR)

The Bubblewrap Trusted Web Activity in `android/` is replaced by a **Capacitor 8** app with the same package
(`io.github.mymayankyadav.lemma`, versionCode 200000+, above every TWA build), installed from GitHub Releases (there
is no Play Console). The React app, screens and kit are unchanged; Android adds system surfaces around them. The plan is
`docs/android/PLAN.md` (the Owner's `05_ANDROID_APP_PLAN.md`); this note records what exists after this PR.

### Phase by phase

**N0 Foundations — built.**
- `capacitor.config.json`; `npm run build:android` = icons → `vite build --mode android` (no service worker, no web-push worker, no PWA manifest; same public Supabase settings as the website) → `cap sync`. Served at `https://localhost/lemma/` so every `/lemma/…` path works as on the website.
- Platform layer `src/platform/`: `native.ts` (`isNative()`, the only thing in the website's first load), `bridge.ts` (the app plugin's typed API), `start.ts` (loaded only inside the app), `links.ts`, `auth.ts`, `timer.ts`, `reminders.ts`, `calendar.ts`, `share.ts`, `voice.ts`, `permissions.ts`, `haptics.ts`, `device.ts`, `NativeWelcome.tsx`. Each has a web fallback or is never loaded on the web.
- Sign-in: Google blocks WebView sign-in, so the app opens Supabase OAuth in a Custom Tab (`@capacitor/browser`) with redirect `io.github.mymayankyadav.lemma://auth/callback` and exchanges the PKCE code in the WebView. **Owner step:** add that URL to Supabase → Authentication → URL configuration → Redirect URLs. (Credential Manager was not used: it needs a new Google library, not approved.)
- App Links for `https://mymayankyadav.github.io/lemma…` (autoVerify). They verify only if `assetlinks.json` (template in `docs/android/`) is published at the origin root with the signing key's SHA-256; that is optional, and without it such links open in the browser. Notification taps, shortcuts and tiles open the app with explicit intents through the same route parser, so they never depend on it.
- Android back: closes the top sheet or dialog, then goes back, from a cold-opened screen goes to Today, and leaves the app only from Today. Predictive back is on.
- Edge-to-edge with Capacitor's SystemBars (CSS `env(safe-area-inset-*)` works as on the web); bar icons follow the page's Day/Night colour.
- Splash: Android 12+ splash (back-ported) with the Notebook icon on the paper colour. Launcher: adaptive icon from the Notebook mark (D3 = C) with a **themed (monochrome) icon**, legacy square and round icons, and the ℓ notification icon, all generated by `scripts/android-icons.mjs`.
- Real haptics: `src/ui/v7/haptics.ts` plays the same patterns through `@capacitor/haptics` in the app.
- "Welcome to the new app" sheet once per install (sign in again; nothing on the server is lost).

**N1 Notifications — built without push.** Channels: Focus timer (silent, ongoing), Focus alerts, Review, Study blocks; each tunable in Android settings. With no push service, the phone schedules what it can compute (`src/platform/reminders.ts`): cards due at the preferred study time (above the due threshold) and planned study-block starts, honouring the Reminders switch, schedule, kinds, quiet hours and "at most N a day". Actions Later (+1 h), Snooze (+10 min) and Not today run without opening the app; Start review and Start now open it. Permission is asked when Reminders are turned on or once after the first finished review round, never at launch; Settings › Reminders shows the state and links to system settings and to "Alarms & reminders". **Not built (D12):** server-sent kinds (tutor, digest, deadlines, behind, resume) on the phone; they stay in the Inbox and Today. Web push is unchanged on the website.

**N2 Native focus timer — built.** `TimerController` and friends (Java): one ongoing notification drawn from timestamps (system chronometer counts up or down; no foreground service), actions Pause / Break (or Park a thought for a pomodoro) / Finish, Resume / Skip break, inline-reply "Park a thought", an exact alarm at each phase end (one-minute window if "Alarms & reminders" is refused; never `USE_EXACT_ALARM`), Android 16 Live Update (segmented ProgressStyle and status-bar chip), the Quick Settings **Focus** tile, and a boot receiver that restores it. Lock-screen actions show at once (marked "syncing"), call `study_command` with the signed-in user's short-lived access token (Keystore-encrypted copy; never the refresh token, which Supabase rotates), and otherwise wait for the web layer to replay them with an `expectedVersion` check so nothing is applied twice. Finish pauses on the server and asks to log ("Save 42 min" or "Rate and save", which opens the finish sheet via `/focus?finish=1`). Drift: returning after more than 2 minutes away during a running focus offers "Log drift" when "Ask about drifting" is on (Lemma's own lifecycle only). The Live Update progress refreshes on every state change and sync, not every second.

**N3 Widgets and shortcuts — shortcuts built; widgets not built (D11: Glance not approved).** Static shortcuts Review, Quick focus, Capture, Inbox; dynamic "Resume <path>" and "Review <n>".

**N4 Capture everywhere — built except the scanner.** Share to Lemma: text and links open Capture filled in; PDF, .tex and .md start a New path with them as sources (the existing upload pipeline). Voice: a Speak button in Capture uses Android's speech dialog (no microphone permission for Lemma). Quick Settings **Capture** tile. **Not built:** ML Kit document scanner (D11) and images → pages (the app has no page-image pipeline; `save_pages` is MCP-only).

**N5 Calendar, Do Not Disturb and Modes — built, opt-in.** Study mode: a "Lemma study" automatic Do Not Disturb rule (shown under Modes on Android 15+) on while focusing, off at pause, break, finish, sign-out, reboot or app start without a running session; on Android 7–9 Priority-only, restored only if Lemma set it. Calendar: blocks written to a read-only local "Lemma" calendar and kept equal to Lemma (insert, update, delete) on every app start and resume; busy times from calendars the learner picks keep Calendar suggestions clear of them; nothing is uploaded. Turning sync off or signing out deletes the Lemma calendar.

**N6 Offline and background sync — partly.** Without WorkManager (D11), refresh happens on app start and resume (reminders, shortcuts, calendar, timer) and lock-screen actions queue natively until replayed. The offline write queue and offline review rounds are not built.

**N7 release and polish — partly; no Play.** CI checks pull requests (Java tests, lint, debug APK) and on main publishes a release APK signed with the Owner's key to a GitHub Release. Done: per-app language config, predictive back, large screens via the existing responsive layouts, data-safety and privacy updates (`docs/android/listing.md`, `public/privacy.html`). Not applicable without Play: store listing, data-safety form, in-app updates and review, Android vitals. Not built: an over-the-air web updater (Carrel uses `@capgo/capacitor-updater`; a new dependency, not approved); TalkBack pass (needs a device).
