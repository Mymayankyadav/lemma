## Legacy conversion first pass

Adds conversion-input reads and fixed instructions, deterministic preservation checks (every old CP mapped, done CPs preserved, reviewed cards retained, matching KCs reused), retry/flag decisions, draft routing and a conversion review table. Conversion proposal application is journalled in the approval transaction.

No conversion of live projects has run. The current application code is an initial implementation: new KC creation, all prerequisite/reference rewiring and complete validation at approval still need the second pass. Do not approve or activate production conversions from this branch until those checks and four-project approval/undo tests pass.

Second pass (chat-91357): `atlas_apply_approved_plan` now applies a conversion completely in the approval transaction. It creates new KCs (reusing an existing concept by id or case-insensitive name, never overwriting its kind; a new KC gets its kind and, when `home` names a topic, its parent), links every created or changed checkpoint to its KCs, rewrites prerequisites from the conversion's own checkpoint ids (done checkpoints keep theirs; edges to skipped or replaced checkpoints are dropped; cycles are refused), steps an old checkpoint aside as `template:replaced` when it is mapped onto a different template checkpoint, requires a decision for every non-deleted card, and refuses any hard-rule violation, leaving the project exactly as it was. The conversion type gained `kcs[].id` and `kcs[].home`; `validateConversion` checks that every template KC resolves. `tests/mcp/sql/atlas-conversion.mjs` runs approve → check → one-action undo → state equals the start on four fixture projects and covers twelve approval-time violations; it fails if the cycle or card-decision check is removed. Still open: the real four-project dry run (cutover, N175) and source/page checks for converted checkpoints.
