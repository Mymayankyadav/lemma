## N192 Offline Local Pad

The P8 workspace can be opened from a v7 checkpoint when the default-off `padLocal` flag is enabled in demo mode. `LocalPadEditor` is a controlled graph-paper textarea with native editing and composition, caller-owned text and selection snapshots, deterministic symbols, explicit template slots and local TeX command suggestions. The preview uses the repository-pinned KaTeX with only bundled assets, isolated macros, HTML and MathML output, and finite source, formula, expansion, dimension and output budgets. Prose and unrenderable formulas stay literal; Markdown does not become a link or embed. There is no transport, provider, route or flag change. Review ScratchPad is still ephemeral.

`LocalPadInk` keeps strokes in a fixed 640×400 space, so a resized or rotated surface does not resample saved points. Draw and Scroll modes separate capturing ink from normal page movement. Canceled or interrupted strokes are never committed; completed strokes have bounded point and record counts. An in-memory undo stack can restore a cleared page. The workspace can explicitly download a versioned JSON backup or a standalone readable HTML copy of the text and completed vector ink. The HTML contains no executable or remote content; TeX stays plain source in the exported notes. A failed download start does not modify the draft. These exports do not include account/context metadata and are not tutor sends.

The separate Pad IndexedDB store follows AND-8's per-owner and atomic transaction pattern without using the expiring, redacted query cache. A checkpoint stores the latest and previous bounded draft revisions (selection, up to 65,536 UTF-16 code units of text, and completed ink). A save checks the expected revision inside the transaction, so an older tab cannot replace a newer save. The session can restore a valid previous revision when the latest is corrupt or explicitly reopen it as unsaved work. A failed save or concurrent change keeps the in-memory draft exportable. Unknown record versions are not overwritten. No sync, network request, server receipt or tutor action is involved.

A compatible local v1 JSON backup (at most 1 MB, with the same bounded draft and coordinate schema) can be opened for preview, including plain text and completed ink. Replacing working content is explicit and does not save until Save draft; cancel leaves the note untouched. Previous drafts use the same review step before replacing work. The fixture UI displays loading, saved, unsaved, recovered, conflict and storage failure states; putting the Pad away keeps the working session open.

The demo entry uses a separate browser database namespace and deterministic fixture checkpoint keys. No live Pad entry is registered. The live adapter filters checkpoint data by owner, but the mounted checkpoint query cache has no owner/generation provenance per result and no verified offline authorization marker. The eventual host must pair the authorized `CheckpointDetail.view.id` with verified `authOwner()` and `authGeneration()`, observe scope changes, and return no scope when authorization cannot be established; a cached route slug/code or email is not evidence. This PR does not alter app-wide auth, permissions or server data.

Browser coverage simulates a network disconnect while saving, portrait-to-landscape resize, checkpoint isolation, and a hash-route remount while still offline. It does not establish a cold PWA launch or physical-device behavior.
