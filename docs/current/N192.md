Each owner has a separate IndexedDB database. A checkpoint keeps its latest and previous draft, including selection, up to 65,536 UTF-16 code units of text and completed strokes. A save checks the expected revision inside the write transaction. A conflict, unsupported version or failed write keeps the working copy available for export. A valid previous revision can recover a corrupt head. The editor previews a previous draft or a bounded portable JSON backup before replacing the working copy. Save draft commits that replacement. Putting the Pad away retains unsaved work in the open checkpoint.

The shared application sign-in and server permissions govern all network operations.

Export Pad backup creates portable JSON. Export readable Pad produces a standalone HTML document containing escaped notes and vector ink. A confirmed deletion clears the matching owner's database and device markers and preserves other accounts' data.
