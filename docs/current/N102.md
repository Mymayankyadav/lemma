## N102 v6 is on by default

`FLAG_DEFAULTS.v6Shell` is `true` in `src/flags.ts`. Everyone gets the v6 shell and screens (Today, Paths, Review, Calendar, Progress, Inbox, Cards, Atlas, Settings and the detail routes); the legacy screens stay in the code behind the same flag.

**Turning it off.** A leading `-` in an override turns a known flag off: `?flags=-v6Shell` or `VITE_FLAGS=-v6Shell`. Overrides are honoured only in dev, test and e2e builds (`import.meta.env.DEV`, `MODE === 'test'` or `VITE_ALLOW_FLAG_OVERRIDES=1`), never in a production build, so a user cannot opt out and rolling back in production is a reviewed PR that sets the default back to `false`. The URL is read after the build-time env, so a build made with `VITE_FLAGS=-v6Shell` can still open a v6 page with `?flags=v6Shell`. `tests/unit/flags.test.ts` covers both directions and the production case.

**Tests.** Unit specs that cover the legacy (flag-off) screens now set `?flags=-v6Shell` in a `beforeEach`: Cards, Checkpoint, Today (`home/n2-*`, `focus/today-focus`), Review count, route lifetime, v6 header and the "legacy live screens" case of the owner-changes sync test. `playwright.config.ts` builds the e2e web server with `VITE_FLAGS=-v6Shell` (a `rules:` change merged before this PR), so the legacy e2e specs keep running against the flag-off app and the v6 specs keep using `?flags=v6Shell`. The rollback spec (`v6-rollback.spec.ts`) still compares the flag-on and flag-off routes and the data that survives the switch.

**Not in this change.** No migration, no function, no screen code. Real third-party calendars, native timers and recurring blocks stay out of v6 (RELEASE.md).

**Release gates.** The PR body lists G1–G7 evidence from `docs/v6/RELEASE.md`. The Owner's explicit approval comment and the Owner's physical-device checks are conditions of merging this PR (D8 g), not something a test proves.
