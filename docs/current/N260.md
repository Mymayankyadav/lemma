## Equation mode only warms from the cache

Opening Equation mode checks installed weights without making remote requests for either the recognizer runtime or its weights. If the cached runtime cannot be verified, speculation stops before reading the large weight files. Cross-origin-isolated pages skip the speculative preparation because their separate pthread helper might not be served by a controlling service worker. An explicit Read still starts the same parallel runtime on isolated pages, and can fetch the packaged, same-origin WASM if needed. **Read equation** still works from healthy cached weights. Missing or corrupt weights bring up the existing approval prompt before any third-party model file is fetched, including when reading from the Scratch pad. For the handwritten equation reader, old weight and runtime entries are replaced only after checksum verification succeeds; a failed repair leaves them and the drawing intact.

In a production-built desktop Chromium demo seeded with truncated entries, the old opening path attempted three remote requests for the tokenizer, encoder and decoder (118 MB total had they been served); the new path made zero while opening, drawing, and clicking Read without approving the download. Regression cases cover with and without a cached runtime. In a manual recovery run using the real pinned weights, requests began only after approval and LaTeX appeared. Healthy installed weights were also read fully offline after a page reload in the same browser context. No deployed headers, ORT parallel helper, inference threads, ink or model settings changed.
