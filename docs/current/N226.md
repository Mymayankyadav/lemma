## N226 Atlas V3 graph integrity and MCP safety

The Owner requested the remaining Atlas audit blockers be completed with ChatGPT/Claude supplying model judgment over Lemma MCP, no external model API keys, and strict release tests. This PR is independent of N225's proposed typed-link creation.

### Safety contract
- Never silently drop attempt tags, instruction events, assumptions, aliases, V3 links, practice-bank rows, recheck decisions or legacy evidence during merge.
- Permit only an audited delete of a truly unreferenced concept. Empty containers are preferred over destructive cascading.
- Reclassification and batch prerequisites use one transaction and one receipt; the database cycle guard remains authoritative.
- Confirm real evidence tags before storing a graded attempt; suggested prerequisites are not proof of skill.
- Maintain cross-subject aliases rather than merging owners' concepts across subjects.
- Preserve optimistic version conflicts rather than silently overwriting learner edits.

### Tests and release
The new command must have real MCP parity coverage (including owner isolation, version conflicts and Undo), a static manifest entry and capability-map coverage. Merge only after CI, scope and independent review of the Supabase migration pass. No existing user data is changed by this PR until approved commands are explicitly invoked.

### Implemented command contract

`study({command:{resource:"atlas_graph_maintenance",operation:"set_level"|"delete_empty"|"reclassify_link"|"link_batch",operationId,schemaVersion:1,target:{id:sourceConceptId},expectedVersion,patch}})` is owner-bound, journalled and idempotent. Set-level checks placement; delete-empty refuses *any* linked data; reclassify-link updates one existing edge in a single transaction; link-batch accepts 1–50 edges for one source, checks targets, and bumps that source only once. The existing `concepts.merge` is protected by an evidence guard and refuses an evidence-bearing source rather than silently cascading away learning history. A worker must never invoke these commands without explicit authorization.
