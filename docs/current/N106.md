## N106 study entry calendar-block association (PR #1193)

One additive migration gives study entries an optional calendar_block_id with an owner-composite foreign key, plus the referenced calendar-block (owner,id) index. Existing entries remain NULL, and deleting a referenced block clears the link without changing the entry owner.

StudyApi.startStudyEntry accepts calendarBlockId. Demo verifies its own study block and persists the link in the tab snapshot; live creates a draft, owner-RLS links it before starting through the existing audited lifecycle, and sends the updated version to the start command. A failed foreign-key validation cannot start a timer. Today re-verifies the plan and block version before passing the actual block ID. Older callers remain unlinked. Full PGlite and Today unit tests cover owner isolation, null compatibility and the actual Start argument.

The v6 capability registry classifies calendar_block_id as an owner-editable, owner-composite link; this is required by both the N40 column-coverage unit test and the N51 study schema acceptance test.
