## N184 The PFA fallback fit converges

`fitPfa` (`_shared/adaptive/fit.ts`) fits the PFA fallback that `serve()` uses when the Atlas model loses to its baseline (D1). It applied every weight's diagonal-Newton step at once. On real data the features are strongly correlated (intercept, KC and system indicators are 1 on every row; success and attempt counts move together), so the joint step overshot and oscillated (0 → .2 → 0 …): after the default 80 iterations, an even number, it returned the prior unchanged. The production cutover export of 2026-11-18 showed this: every weight at its prior, the fallback predicting .5 (log loss .693, worse than the base rate's .604).

Now each iteration takes the same direction but halves the step until the penalised log-likelihood improves (backtracking), and stops when no step helps; the default is 200 iterations. On the production export the fallback fits log loss .581 (base rate .604, Atlas model .563). Nothing else changes: the PFA is used only by `serve()` when D1 fails and in the diagnostics, and the simulation gates come from `research/sim` (Python), not from this function.

The cutover's `model_fits` row (docs/current/N180.md step 7) is computed after this fix, so it stores the fitted fallback.
