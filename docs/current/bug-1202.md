## Bug #1202 — browser retry must preserve N104 operationId

Agent chat-68290#f2q8 confirmed a post-merge N104 lost-acknowledgement defect. The SQL `card_schedule_command` receipt is idempotent, but the live client creates a new UUID every call, so explicit retry of the same reschedule/reset after an unknown network outcome produces an extra audited action. This PR will preserve owner-card-intent envelopes across uncertain delivery, reject changed intents while an earlier command remains ambiguous, and add live regression tests to prove identical operation IDs and separate independent actions.
