## Checkpoint tutor chat

**Continue with tutor** opens a checkpoint conversation inside Lemma’s normal app layout at `/p/:slug/cp/:code/tutor`. A project link resolves to its current checkpoint or offers a checkpoint choice. The app’s mobile navigation, desktop sidebar, Back control, search, appearance settings and device commands stay available throughout the conversation. The supplied design guides the study overview, session controls, message bubbles and math keyboard, implemented as React components using Lemma’s shared headers, buttons, sheets and theme. The tutor uses the selected checkpoint, and the learner can preview and attach a source page or an excerpt. The Pad editor has moved out of the checkpoint and main navigation. Saved notes remain available under **Settings → Data and account** and at the existing Pad and offline recovery URLs.

Direct tutor links return to the checkpoint with Back, and opening the tutor preserves the checkpoint’s original recent-item link. The composer accounts for the app’s navigation and active focus row. On short phones its math keyboard opens on demand, keeps the answer controls visible and scrolls its keys within the available space. The device keyboard uses the visible viewport when it covers part of the page.

**Send** saves a learner turn through the checkpoint owner command. For an enabled connector it also issues a grant for the returned server turn ID. The installed Lemma MCP connector discovers authorized turns with `get({what:"tutor_turn"})`, reads a specific handoff by its public reference, and uses `study` to claim the turn and reply. The tutor receives the prior question from this checkpoint to interpret a short follow-up answer. The dedicated turn-bearer profile and manual reply import remain available. The transport uses the existing lease, receipt and single-final-reply contracts.

A visible conversation refreshes while a reply is pending and on return to the app. After replying, an active host can call `get({what:"tutor_next", id:<completed handoff>})` once to wait briefly for the next answer in the same thread. Each learner answer has its own grant. The launch link lets the learner prompt an idle Claude or ChatGPT session using the public handoff reference. The browser keeps drafts and interrupted submissions scoped to the signed-in account. The local demo supports saving a conversation and importing a reply in that browser.

The tutor page is enabled in the v7 client. Live writes require the existing shared server release, the `manual` control for new questions, and the `mcp` control for connector grants and replies. Release holds preserve receipt checks, confirmed history and draft recovery. The regular connector additionally requires the N201 migration and matching MCP function deployment.
