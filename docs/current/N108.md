## N108 — canonical day close with carry-over

The close command now takes a plan version, optional JSON ritual, an optional `tomorrow_first_task_id` and optional `carry_over` task selections. Each selection is either an owner task ID (default reason: "Carried over to tomorrow") or a `{task_id,reason}` descriptor. The server rejects future local plan days, non-committed plans, missing or foreign tasks, duplicate selections and malformed reasons before writing. A single atomic command closes the plan, updates its tomorrow-first-task link and sets the selected plan items to `carried_over`, clearing any block link, while preserving audit action, idempotent receipt and undo.

The typed DayPlanApi keeps the existing `closePlan(id,version,ritual)` call valid and accepts an optional fourth `DayCloseTransition` parameter. Both demo and live validate selections. The static command resource registry and N94 parity expectations include the additive carry-over field.
