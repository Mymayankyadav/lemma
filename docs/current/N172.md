## Atlas v3 consolidated first implementation (N172–N179)

Owner requested the v3 pack first, with corrections in a second pass. PR #1501 consolidates the dependent work. The source pack is in `docs/spec/atlas-v3/`; the supplied Python research harness is in `research/sim/`.

Implemented in this pass:
- Shared KC FSRS memory and hierarchical execution ADF, hint/stage/legacy handling, coupling hypotheses, online mixture, PFA fitting and diagnostic helpers.
- Additive owner-scoped attempt, tag, instruction, link and model-fit schema; registered owner commands, journal triggers and manual rollback.
- MCP reads and attempt writes; duration/attendance and KG helpers; course/card policy and conversion validation; React primitives and screen integration.
- Numerical golden comparisons against the supplied Python FSRS and likelihood primitives on three held-out seeds; pure-model, display, MCP parity and SQL migration tests.

This is a first implementation, not a cutover release. No production database operation or project conversion has run. Existing Beta and N169 serving paths remain until the approved N175 cutover. The branch intentionally has no Ready comment.

Second-pass acceptance work:
- Reproduce the complete KF/PFA/card model against the research harness and run the full two-world held-out and paired end-to-end simulation gates. Golden primitives alone do not establish those gates.
- Complete all four diagnostic streams and serving calibration, the causal KG action simulation, v3 scheduler write-through/prune/restore, final-day reviews and multi-project allocation.
- Complete conversion application for new KCs, prerequisite/reference rewiring, source checks and full approval-time hard-rule validation; test approval plus undo on copies of all four projects.
- Finish Atlas filters/bridge rendering, planner slot selection and the remaining detailed UI acceptance cases.
- Obtain the specified independent backend review and protected-test/CI changes through the repository's rules process, then remove Beta/EWMA paths and run the production dry-run gates before any cutover.

A cold local replay of 5,000 one-tag attempts took 139 ms on the first pass. The takeover (chat-91357) indexed the per-event lookups (`replay` built them with linear `find`/`filter` over tags, sessions, items, cards and a rebuilt concept map per observation, so it was quadratic): the same replay now takes about 100–115 ms cold and about 52 ms warm (Node 22, 40 concepts, 5,000 one-tag attempts with embedded tags; 1,070 → 105 ms cold when the tags are a separate fact table). Output is identical (same mixture weights and trace). **The 50 ms cold target is still not met**; the remaining cost is allocation and GC in `updateTrial`/`pfaFeatures`/`trace`. No performance threshold was changed.

Diagnostics (chat-91357): all four streams of 01 §9 now report. `_shared/adaptive/diagnostics.ts` adds the durations stream (log-normal model against a running log-mean baseline, PIT uniformity D4, 80% coverage D5 with the widening factor) and the attendance stream (kept/missed blocks against the running base rate; calibration D2 and randomized PIT D4), in the same `Health` shape as the attempt and card streams (`diagnose`). Fewer than 50 events show `insufficient data`, never a pass. `assembleAtlas` records each prediction before the duration and attendance filters absorb the observation and returns `health` for attempt, card, duration and attendance. Tests: `tests/unit/adaptive/diagnostics.test.ts` (calibrated passes, too-narrow intervals fail D5 and D4, a worse-than-baseline model fails D1, an over-confident attendance predictor fails D2). Not done: the Python-harness reproduction of the full KF/PFA/card model (the TypeScript core extends the research KF with ancestors, facets, links and two coupling hypotheses, so a prediction-for-prediction golden needs a research-compatible mode first) and the two-world held-out and end-to-end simulation gates, which need scipy/scikit-learn and long seeded runs.

Simulation gates (chat-91357, 18 Nov 2026; harness in `research/sim/`, Python 3.13, numpy 2.5, scipy 1.18, scikit-learn 1.9). The shipped harness lacks `test_specs.pkl`, `test_cspecs.pkl` and `e2e_hp.pkl`, so I rebuilt them from the tune stage (best variant per family by mean KL over both worlds, seeds 1000–1007: Beta, v2_0, pfa_0.5_0.3, das_0.3_0.3, kf_1.0_1.0, gb_a; cards c_def, c_map_.3, c_cpl_0.2, c_rich_0.3_0.2; e2e hyper-parameters kf al=1 mS=1, v2 vk=.25 q=.005, card couple=.2 resid). These are my reconstruction, not the author's files.
- **Held-out attempts (seeds 2000–2011, 12 learners per world):** KF KL to the true p = 0.0346 ± 0.0016 (W1) and 0.0431 ± 0.0015 (W2) against v2 0.0880 and 0.1033, i.e. 58% below v2 in the weaker world (gate ≤ 0.040 / ≤ 0.050 and ≥ 40%). Learning curve (attempts 1–30 → 200+): 0.045 → 0.028 (W1), 0.050 → 0.040 (W2). Calibration slope 0.90 (W1) and 1.04 (W2), |intercept| ≤ 0.16, fatigue |z| ≤ 1.6. These reproduce the figures in 09 to the printed digit. PFA 0.049/0.053, DAS3H 0.051/0.052, Beta 0.085/0.091, gradient boosting 0.105/0.112.
- **Cards:** coupled model c_cpl_0.2 averages 0.0386 against default FSRS 0.0430 (−0.0044; W1 0.0722 vs 0.0816, W2 0.0049 vs 0.0043).
- **Durations and attendance (`time_sim.py`):** Kalman log predictive density −0.655, 80% coverage 0.83 (EWMA −0.973 / 0.71, NIG −0.861 / 0.79); attendance log loss 0.560 (declared 1.300, ratio 0.576); Thompson calendar 68.0 min/day against fixed 65.6 (+3.7%), oracle 74.8.
- **End to end, paired (seeds 3000–3005, 6 per world, 12 pairs — fewer than the pack's 10 per world):** P2C − P0 = +0.0068 ± 0.0034 (W1), +0.0160 ± 0.0048 (W2), +0.0114 ± 0.0031 overall (3.6 SE); P1-style allocation −0.047 ± 0.009 (stays removed); oracle +0.024.
- `research/sim/gates.py` turns these outputs into the `gates` object of the release report: every measurable gate passes; the two token gates (resume ≤ 1,500, cards ≤ 100) come from the TypeScript side and are the only ones missing. `tests/unit/adaptive/gate-thresholds.test.ts` keeps its thresholds equal to the activation SQL.
- **Not a statement about the TypeScript core.** The harness `KF` is the research model (single hypothesis, no ancestors, facets or links); the production `replay` extends it, so these gates validate the evidence and the hyper-parameters, not `replay` prediction for prediction. A research-compatible mode in `replay` (so a golden stream can be compared to 1e-6) is still open, as is the production-replay diagnostics acceptance (07 Acceptance 3).

Replay speed, second round (chat-91357): interned component ids and cached ancestor lists (a fresh 'kc:'+id string made every `components` lookup hash again) and a loop in place of `Object.entries` in the PFA sum bring the 5,000-attempt replay (embedded tags, same machine and bench as above) to about 90 ms cold and about 45 ms warm, output identical. The warm figure is under the 50 ms target; the cold figure is not, and what is left is JIT warm-up plus allocation in `updateTrial`/`consumeAttempt`, which would need a typed-array state to remove.

Research mode and the shipped model (chat-91357): `replay(facts, fit, now, {research:true})` is the harness KF of `research/sim/models.py` inside the production code: one hypothesis; global, system, KC, learning and fatigue terms only; the harness derivative (no probit attenuation factor), its 1e-4 variance floor and priors (KC sd √.5, learning variance .1); fractional days with the harness's same-day rule (an interval under half a day is a same-day update). On the harness's own simulated worlds it reproduces the Python KF prediction for prediction (max difference 1.7e-8 over 12 + 12 held-out learners and about 6,000 attempts; `tests/unit/adaptive/atlas-v3-kf-golden.test.ts` asserts 1e-6 on a synthetic course and on two real world streams, golden files from `research/sim/golden_kf.py` and `export_stream.py`). Research mode gives 0.0346 (W1) and 0.0431 (W2) mean KL, the same as the Python figures.
The shipped model is not the research KF, and this is what the gates now measure for it (`research/sim/ts_kl.mts`, 12 held-out learners per world, the same streams): mean KL to the oracle **0.0375 (W1) and 0.0453 (W2)**, against the gates 0.040 and 0.050, and 57% / 56% below v2 on the same learners; with the PFA mixture 0.0341 / 0.0427 on the first four learners. It is about 8% worse than the research KF in W1 and 5% in W2 because of the exact derivative, facet, cross, ancestor and link terms and the two coupling hypotheses; the simulation gates therefore hold for the code that ships. `research/sim/gates.py --ts-kl ts_kl.json` uses those numbers for `kf_kl_w1`, `kf_kl_w2` and `kf_reduction_vs_v2`; calibration, fatigue and the card model are still the research model's (the card stream of the shipped model is not scored).
