## N53 pending commands: owner-scoped scheduler and database worker (chat-94357#z6m2)

The N53 branch introduces owner-select-only pending_commands with two distinct idempotency identifiers: each schedule/extend/cancel control envelope uses a fresh owner operationId receipt, while the scheduled registered-resource payload retains its own immutable execution operationId. The authenticated pending_command SQL RPC validates registry/operation membership, owner-free payloads and ISO-offset execution/undo windows; a row/version lock controls extension and cancellation, and exact retries replay stored command_receipts without duplicating work. Service-role-only lemma_run_due_commands selects one due row FOR UPDATE SKIP LOCKED per transaction (to preserve log_change's one-action/owner audit boundary), dispatches through the existing registered mcp_command and marks succeeded/failed (sanitized error class) in the same database transaction. A crashed transaction rolls back its claim, and a subsequent tick cannot repeat terminal rows. The successful underlying command produces a normal actionNo undoable through undo_action. The production worker runs from an every-minute `pg_cron` job installed conditionally in the same migration when the extension exists. On hosted Supabase the cron job runs as `postgres`; one invoker-level anonymous SQL block switches to `service_role` only locally before calling `lemma_run_due_commands`, satisfying the worker and the existing `mcp_command` trusted-role check without a browser timer, Edge route or secret. PGlite has no `pg_cron` and skips this installation. The old optional notify tick-core hook remains purely auxiliary, not the production delivery path. The scheduled job invokes one owner action per database transaction, so each minute executes at most one due command; later ticks handle additional rows. Full-migration SQL and tick unit tests cover owner RLS, receipt conflicts, extension/cancellation, failure, repeat ticks and undo. This PR is not deployed; CI and independent SQL review are required.
