## N53 pending commands: owner-scoped scheduler and database worker (chat-94357#z6m2)

The N53 branch introduces owner-select-only pending_commands with two distinct idempotency identifiers: each schedule/extend/cancel control envelope uses a fresh owner operationId receipt, while the scheduled registered-resource payload retains its own immutable execution operationId. The authenticated pending_command SQL RPC validates registry/operation membership, owner-free payloads and ISO-offset execution/undo windows; a row/version lock controls extension and cancellation, and exact retries replay stored command_receipts without duplicating work. Service-role-only lemma_run_due_commands selects one due row FOR UPDATE SKIP LOCKED per transaction (to preserve log_change's one-action/owner audit boundary), dispatches through the existing registered mcp_command and marks succeeded/failed (sanitized error class) in the same database transaction. A crashed transaction rolls back its claim, and a subsequent tick cannot repeat terminal rows. The successful underlying command produces a normal actionNo undoable through undo_action. The notify tick core invokes the optional service-role runDueCommands adapter once before owner enumeration and independently of notification subscriptions; wiring the production Edge adapter remains an integration prerequisite, as no server route changes are in N53 scope. Full-migration SQL and tick unit tests cover owner RLS, receipt conflicts, extension/cancellation, failure, repeat ticks and undo. This PR is not deployed; CI and independent SQL review are required.
