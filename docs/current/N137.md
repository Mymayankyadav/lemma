## N137 G1 the asset pipeline (13 Nov 2026)

Plan r3 (`docs/v7/ux-audit-2026-11-12/04_ASSETS_AND_MOTION_PLAN.md` §3) asks for every asset to be generated, listed
and linted, so nothing can drift from its source. What exists now:

- **`assets.manifest.json`** lists 37 generated assets: the web icons, the Android launcher layers and legacy icons,
  the themed and notification icons, and the Android colours. Each entry gives its source, generator, size, themes,
  byte budget and where it is used.
- **`scripts/brand/asset-lint.mjs`** runs after every `npm run build` (`postbuild`, after `check-pwa.mjs`). It fails
  the build when:
  - a listed file is missing or over its budget;
  - a PNG has the wrong size;
  - a committed generated file differs from what its generator writes today;
  - a committed generator writes a file the manifest does not list;
  - the mark's ℓ on paper falls below 7 : 1, or its ∎ below 3 : 1, in Day or Night.
  Running it as a CI check of its own is an Owner `rules:` PR.
- **Android colours from the tokens.** `scripts/brand/android-colors.mjs` writes `values/colors.xml` and
  `values-night/colors.xml` from `src/ui/v7/design-tokens.json`, and `npm run build:android` runs it. The colours
  are unchanged, but they now come from one source: the page from `surface.page`, the brand indigo from `action.bg`,
  and the dark primary from `text.primary`.
- **The adaptive icon in two layers.** `scripts/android-icons.mjs` now writes `ic_launcher_background.png` (paper,
  graph grid and margin rule, extending to the layer's edge) and `ic_launcher_foreground.png` (only the ℓ and the ∎).
  The adaptive icon XML points at both. Composed, the two match the old single-layer icon within 2/255 per channel. The
  launcher's parallax now moves the writing over the page. `rasterMark` gains a `parts` option, and its default output is
  byte-identical to before.
- **The emblem exporter.** `src/ui/v7/emblemExport.ts` has three outputs from one generator:
  - `emblemSvg`: a standalone SVG with the `Emblem` component's exact strokes and frame;
  - `emblemStrokeOrder`: the strokes in drawing order with their lengths, and when each draws in a single draw-in,
    timed by length so the pen keeps one speed;
  - `emblemPng`: a browser canvas PNG at any size and colour, for Android notification art made on the device.

  `npm run emblem -- --subject <S> --seed <seed>` writes the SVG and the stroke list.
