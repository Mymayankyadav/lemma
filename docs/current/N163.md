## N163 — a timer started, paused, resumed or finished from chat reaches the phone through Firebase Cloud Messaging

**Owner task** (14 Nov 2026): "Ok let's setup fcm", after "when I start timer from claude it does not create a notification right away. I have to open the app to have time in notification." (bug #1408). Owner decision: Firebase Cloud Messaging only; scope = the timer first (this item), every notify kind next (N164). The rules change that lifts the 12 Nov ban (D11/D12) for messaging only is the `rules:` PR "allow Firebase Cloud Messaging …"; this item needs it merged first (the Android shell check still refuses Firebase until then).

### How it works

1. **Token.** The app starts Firebase from four public values in `android/app/firebase.properties` (no google-services plugin; blank = off, the app builds and behaves as before), asks for this phone's token, and the web layer sends it with `register_push_token(device_key, token, app_version)` (`src/platform/push.ts`, on start, sign-in and a new token; `unregister_push_token` on sign-out). Table `device_push_tokens`: one row per device, owner-scoped, writes only through those functions.
2. **Queue.** A trigger on `study_entries` writes one `push_outbox` row for every change of a running or paused entry (created, started, paused, resumed, other phase, renamed, saved, discarded, deleted) and calls `push_kick()`, which posts to the `push` Edge function with `pg_net`. It never raises: a study command cannot fail because of a notification. `pg_cron` retries every minute (`push_retry`), gives up after three attempts or ten minutes.
3. **Send.** `supabase/functions/push` claims a batch (`push_claim`), reads each entry as it is now (so quick changes send one message and a late retry is never stale), builds the phone's timer state (`supabase/functions/_shared/timerState.ts`, the server twin of `nativeTimerState`, pause-aware like N162) and sends a high-priority FCM data message `{type:"timer", op:"show"|"clear", entryId, version, state}` (60 s time to live, collapse key `timer`) to every token of the owner. A token FCM no longer knows (UNREGISTERED) is deleted.
4. **Show.** `LemmaMessagingService` receives it with the app closed and applies it with the same `TimerController.show` / `clear` as `timerUpdate` / `timerClear`. `PushMessage` decides: another entry replaces; the same entry only with a newer version; a lock-screen action not yet sent wins over an equal version; a clear only for the entry that is showing. When the app is open it re-syncs from the server as before.

### Owner setup (one time; none of this goes in chat or the repo except the four public values)

1. Firebase console → **Add project** (Google Analytics off) → **Project settings → Your apps → Add app → Android**, package `io.github.mymayankyadav.lemma`. Download `google-services.json` once, only to read four values from it (do not commit it): `project_info.project_id` (projectId), `project_info.project_number` (senderId), `client[0].client_info.mobilesdk_app_id` (applicationId), `client[0].api_key[0].current_key` (apiKey). They are in `android/app/firebase.properties` (project `tame-16ba8`, committed 14 Nov 2026); they are public client identifiers.
2. In Google Cloud console for the same project, make sure **Firebase Cloud Messaging API (V1)** is enabled.
3. Firebase **Project settings → Service accounts → Generate new private key.** In the Supabase dashboard → **Edge Functions → Secrets**, add `FCM_SERVICE_ACCOUNT` with the whole JSON file as its value. Delete the downloaded file afterwards.
4. Make a random shared secret (`openssl rand -hex 24`). Add it as the Edge Function secret `PUSH_SHARED_SECRET`, and in the Supabase SQL editor run `select vault.create_secret('<the same value>', 'push_shared_secret');`.
5. Merge the `rules:` PR first, then this item. The deploy workflow deploys `push` after the migration. Install the new APK, open it once while signed in (it registers the token), close it, and start a timer from chat.

Until steps 1–4 are done nothing changes for the user: no values means no Firebase on the phone, and no secret means `push_kick` and the function do nothing.

### Tests

`tests/unit/push/{fcm,handler,timer-state}.test.ts` (JWT signing and verification with a generated key, FCM request shape, every answer mapped, the outbox drain, parity with the app's timer state), `tests/mcp/sql/push-fcm.mjs` (tokens, RLS and grants, trigger, claim, retry, a failing outbox never fails a study command), `tests/unit/platform/push.test.ts`, `android/app/src/test/.../PushMessageTest.java` (run on the JVM with the real `org.json`). The classes that touch Firebase (`PushToken`, `LemmaMessagingService`, `LemmaApplication`, the plugin's `pushToken`) could not be compiled in the agent's container (no Android SDK): CI's Android build is their first compile.
