## Full-equation WASM workers on isolated pages

When the existing policy selects multiple threads, the Pix2Text worker now gives ONNX Runtime its own standalone Emscripten module URL. Previously its nested pthreads could re-enter Lemma's bundled recognizer instead, leaving the UI on “Reading…”. The matching 24 KB helper comes from the already pinned runtime, is served by the app and is in the PWA offline shell. It contains no model weights. Nonisolated pages keep their single-thread path; no production headers, consent or thread counts change.

**Verification:** In the production-built Tutor → Equation mode → Read flow, the same four-stroke input returned the same LaTeX in desktop Chromium with real installed model files. On a loopback origin deliberately configured with COOP and COEP, the previous four-thread setup produced no result within 120 s. In a controlled comparison on that isolated origin, forcing a single thread returned visible results in a median 2.88 s warm; four threads with the matching module took 1.09 s warm (three reads for each). These are not timings for a live nonisolated deployment, an iPad or an Android device, or a claim about first-time downloads. The helper was also tested under same-origin worker CSP online, and after an offline page reload in the same browser context with the shell, runtime and weights installed. No process restart or physical mobile device was tested.
