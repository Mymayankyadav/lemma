## N104 — audited card schedule corrections and v6 controls

The additive `card_schedule_command` has two owner-bound commands, `reschedule` (an explicit offset-aware due instant, preserving scheduler history) and `reset` (state New with zero learning counters and today's due instant). Both target a card through its owner note number and exact variant ordinal. A server transaction checks `auth.uid()`, validates the full envelope, locks the selected owner card, journals the changed card once, returns a stable operationId receipt, rejects changed-payload retries, and registers the same command for MCP. `undo_action` restores the prior card snapshot. No browser service key, migration rewrite, or direct table mutations are used.

Demo and live `LemmaApi` implement both operations. The v6-only `CardVariants` display has per-sibling reschedule datetime input and a two-step confirmed reset, and re-reads the authoritative owner card before showing success; errors stay visible. The feature remains behind the existing `v6Shell` mount with no legacy page changes. Focused tests cover owner isolation, sibling selection, exact retry and changed payload, restored undo, MCP, demo history retention, owner-free RPC envelope, and v6 controls.

Production changes require independent SQL review and passing CI before merger. The new feature is not deployed by this PR until approved and merged.
