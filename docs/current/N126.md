## N126 No "could not open what was shared" toast on every return to the app (12 Nov 2026)

**Report:** on Android 2.0.594 the toast "Lemma could not open what was shared. Try again." appeared every time the
Owner switched back to Lemma, with nothing shared.

**Cause:** the app's plugin returned its lists with Capacitor's `JSArray.from(List)`, which accepts only Java arrays and
returns `null` for a List. The share check runs on every resume; it read `items: null`, its loop threw, and the catch
showed the toast. The same `null` reached the pending lock-screen actions (so they were never replayed), the device
calendar list and the busy times. (Before N125 no plugin call worked at all, so this only surfaced after that fix.)

**Fix:** `LemmaNativePlugin.result()` puts the `JSONArray` itself, never `null`. On the web side `sharedItems()` treats a
missing list or a failed call as "nothing shared" and stays silent; the toast now appears only when a share that was
actually received cannot be opened. Pending actions, calendars and busy times also accept a missing list.

**Tests:** `PluginResultTest` (JVM; shows `JSArray.from(List)` is `null` and that results carry the array) and the N126
cases in `tests/unit/android/platform.test.ts`.
