## N222 autoeq decoding for Equation Assist

In development and test builds, enable `equationAssist` in the existing
feature-flag query. For example, open
`/lemma/?demo=1&flags=v7Shell,equationAssist#/pad?path=real-analysis&checkpoint=CP4`.
The flag defaults off for production builds.

Open **Equation Assist** in the Pad and select a single bounded expression or
declaration. The picker previews LaTeX and edits the selected span only when
the learner chooses a reading. Pad's existing undo applies to the insertion.
An active IME or a changed selection prevents a stale candidate from being
applied.

`root 2` offers a square root. A selection like `x2+y2=2` offers distinct
power, subscript, and coefficient readings. Nearby terms such as *circle*,
*sequence*, and *linear equation* rank those readings. Supported polynomial
declarations and explicit quantifiers receive LaTeX candidates from local
rules. When a polynomial's indeterminate is unspecified, the reading that
preserves that wording is offered first.

The fallback uses autoeq v1.4's original Apache-2.0 INT8 weights and vocabulary.
Its pinned graphs total about 4.2 MB. In simple typed algebra, each beam tracks
which letters, digits, signs, comparison symbols, and divisions it has copied.
The decoder masks expansions that would change those facts before ranking
tokens. A completed beam must parse as algebra. The resulting tree collapses
typographic variants and preserves distinct scopes such as `a+(b/c)` and
`(a+b)/c`. Search continues for at most six steps after the first valid beam.
Named operators, scientific notation, and other syntax outside this constraint
use the upstream decoding path.

The worker receives only the bounded selection. It fetches verified static
assets from Lemma and shares the packaged ONNX Runtime WASM binary. The web
app can reuse cached assets offline after first use. Capacitor bundles the
assets with the Android app.

Typing shortcuts such as `sqrt(`, `frac(`, and `x^` offer only notation slots.
The learner chooses a slot and supplies its contents. The typing path uses
Pad's existing templates and leaves model inference to Equation Assist.

### Benchmark

Run `node --import tsx scripts/equation-assist/benchmark.ts`. Add `--json` to
inspect the candidates for each annotated case. Both decoders run with the
same checkpoint and beam width. The selected-text tests exercise the complete
candidate algorithm, including phrase rules and optional context.

| Correctness measure | Stock autoeq | Refined |
| --- | ---: | ---: |
| First choice on typed algebra | 18/18 | 18/18 |
| Every required reading on ambiguous typed algebra | 5/5 | 5/5 |
| Typed suggestions outside the annotated readings | 28 | 0 |
| First choice on selected text and optional context | 4/14 | 14/14 |
| Every required reading on ambiguous selected text | 0/2 | 2/2 |
| First choice on complete upstream expressions | 181/181 | 181/181 |

The curated selection cases cover supported English phrases, including roots,
comparisons, coefficient domains, and explicit quantifiers. The upstream
regression uses its published Apache-2.0 ambiguity suite and measures first
choices on the 181 complete expressions. Its six incomplete expressions are
for the upstream autocomplete behavior.
[Upstream fixture](https://github.com/mie00/autoeq/blob/ca8fdda9fe8311b0b9b4cd2e7a591f2b66a292f5/tests/ambiguity_suite.jsonl)

Warm single-thread WASM decoding added about 2.5–6.5 ms to the median for
typed cases across three runs on the shared desktop runner. Tail latency varied
between runs. The timings start after the model has loaded.

Verification also covers notation slots, undo, cancellation on reselection,
offline model reuse, and the existing Pad keyboard and symbol recognizer. Web
tests use a 390 × 844 Chromium viewport. The Android web build and Capacitor
sync include both verified graphs and one shared WASM asset. Physical Android
latency has yet to be measured.
