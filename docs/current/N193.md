## N193 — Durable tutor and manual handoff foundation

This PR's first pass adds pure turn and reply transitions, not a working or durable Tutor screen. Nothing calls them from the app or MCP yet. They take a supplied current thread head and turn; there is no second store, network call, or new authority.

Submission snapshots the question and only the selected, versioned context. Later editing does not touch that snapshot. The manual preview preserves the pasted body as text, marks it “Imported by you,” and does not interpret it as an instruction. An accepted connector reply can cite only an item and version in the submitted snapshot; a reported connector host name is explicitly unverified. The first accepted reply is final and the losing candidate is returned as a recoverable draft. Suggestions are only draft proposals tied to the source message; accepting a reply never approves or writes a study outcome.

The next change belongs on this same PR: connect the transitions to P3's derived-owner checks, atomic head/version checks, uniqueness constraints and operation receipts. These pure transitions cannot enforce race safety on two different devices. Wire the composer, bounded selected-context preview, manual copy/import and recoverable drafts, then reuse the existing approval surfaces. Add foreground reconciliation, scoped grants, claim/renew/expiry/generation checks and transactional race tests before considering any external host. No provider is activated by this pass.
