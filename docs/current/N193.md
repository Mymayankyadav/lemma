## N193 — Durable tutor and manual handoff foundation

The pure turn model seals the selected, versioned context and leaves later draft edits alone. Manual import keeps the pasted text as data and labels it “Imported by you.” Connector citations are restricted to the saved selection, and a connector's reported host is not proof of origin. Accepted suggestions are proposal drafts, not study writes.

The demo-only manual adapter now stores one confirmed thread per fixture profile, path and checkpoint, separate from live study data. Browser tabs share an IndexedDB write transaction: they see one final reply, and the losing paste remains recoverable after reopening. The existing v7 checkpoint now offers a separate manual tutor preview with `?demo=1&flags=v7Shell,tutorManualDemo` in development/test builds. The flag is off by default; live mode cannot show it. Unsaved question and paste text survive route changes and reload in the same tab; Escape or Cancel discards only the import preview, not the paste. The user explicitly chooses whether to include the bounded checkpoint objective, copies the sealed handoff text, and previews the pasted reply before saving it. Nothing opens a provider, sends a message, or calls a backend. The two browser tests exercise the actual checkpoint workflow as well as reload, cross-tab finalization, retry and checkpoint isolation in the adapter. This is fixture storage only, not a sync or backup guarantee.

Local excerpts use their own kind: `previewLocalTutorExcerpt(selectedText)` then `addLocalTutorExcerpt(preview)` on explicit Add; Save snapshots a single exact excerpt of at most 1,200 UTF-16 code units. The composer can preview and remove this independently of the checkpoint objective. It cannot resolve citations, does not look up or transfer a Pad record, and is scoped to the existing demo-only preview. The Pad producer is not connected in this PR.

Live integration still needs one authenticated transaction per operation: derive the owner from the actual session/grant, check path/checkpoint/turn membership, look up an immutable operation digest and expected version per P3, atomically advance the thread or finalize the turn, and acknowledge only after the authoritative reply and receipt commit. Enforce database uniqueness on one pending turn per thread and one final reply per turn. Keep the rejected attempt's text in an owner-scoped recoverable draft without replacing the reply. Re-read authoritative state on foreground return; preserve drafts on conflict and gate late callbacks by account epoch and attempt generation. Link proposals to existing review without approval and then verify each narrow host operation, including revocation and lease expiry. Keep all further P6 work on this PR.
