## N193 — Checkpoint tutor

The v7 checkpoint composer saves one owner-scoped conversation per path and checkpoint. A question seals its text and the context the learner reviewed. The learner can include the current checkpoint objective, a verified page excerpt from its linked source, and one explicitly added local selection of up to 1,200 UTF-16 units. A connector can cite only the versioned checkpoint or source page present in that snapshot. Later typing stays in a separate draft.

Manual handoff copies the saved question for an external tutor. The learner previews a pasted answer and confirms the import. The thread labels it “Imported by you.” A compatible MCP host can use an owner-created, one-day grant at the separate tutor endpoint. It lists four tools for reading one turn, claiming it, renewing its five-minute lease, and submitting a reply. The server checks the grant and generation on every operation. Switching tutors revokes earlier grants. If a host supplies its name, the UI identifies it as self-reported.

The same transaction arbitrates a confirmed manual import and a connector reply. One reply wins. The other remains available under Recoverable replies. The local outbox retains ambiguous database submissions with their original operation IDs. Reopening or returning to the foreground rechecks authoritative state and fills missing history pages. An offline owner can read the last confirmed conversation from a previously available checkpoint. The owner alone can send a card to ordinary proposal review. Suggested plans and edits also enter that review path. A completed reply links to matching active study sessions where the learner can record their own evidence or summary.

### Release requirements

The default-off `tutorThreads` build flag requires the shared server launch capability. New questions and external grants additionally need the corresponding `manual` and `mcp` entries enabled in `tutor_release_controls`. Disabling a transport after launch preserves history, export, drafts and manual recovery. The trusted command receipts require N191 and its separately reviewed permissions cutover. The owner snapshot and both keyset export routes include the transcript and grant metadata through N191’s private export registry. Account deletion removes those records and the private credential verifier.

Local tests cover PostgreSQL 17 connection races in both arrival orders, changed/duplicate requests, stale leases, release rollback, owner separation, reviewed card and plan changes, versioned source citations, owner exports and account cleanup. The HTTP profile test uses the pinned MCP SDK. Manual handoff is available independently of host-specific verification. Branded host/account/phone compatibility and direct plan inference require their own evidence before they can be advertised.

The original IndexedDB demo remains available through `?demo=1&flags=v7Shell,tutorManualDemo` in development and test builds.
