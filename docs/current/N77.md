## N77 v6 activity preset Settings manager and Focus picker (chat-21963#n6w4)

The N77 branch adds an Activities tab exclusively within the v6 Settings surface while retaining the original seven legacy N28.1 section IDs for existing keyboard/navigation contracts. Activities use the N55 mode-aware PresetApi for bounded full owner-list paging, typed create/edit, precise nonnegative order changes, archive and restore, never raw browser DML. Save, validation and server errors are surfaced visibly; failed edits are retained, while archived presets remain available to restore. The independent src/features/focus/PresetPicker.tsx reads all active owner presets and prepares the selected label/intent, related subject/project/checkpoint IDs, mode and timing settings for a Focus start callback; it cannot mark an archived preset active or independently start a study entry. N72 owns the authoritative captured session configuration when that command lands. Dedicated tests cover all manager operations, typed validation, error handling, >50 owner pages, stable cursor refusal and picker-only active options. No feature flag defaults or data adapters changed. **Integration gate:** the existing Focus start control lives in src/features/focus/TodayFocus.tsx, which N77's permitted scope excludes. Therefore the standalone picker is prepared but cannot be mounted in Focus until a scoped Owner-approved integration step; an explicit issue tracks this constraint. Do not mistake the standalone picker for a rendered Focus start selector.


N77 CI correction: native HTML min/max validation on the Activities form previously suppressed the React form submission when a timing value was invalid, so the explicit accessible error could never render. The form now uses `noValidate` and its stricter typed JavaScript validator; the negative regression remains in place. CI revalidation pending. The current N77 permitted scope still cannot mount the picker in TodayFocus; see issue #1123.
