## N190 Settings search destinations and keyboard history

- Before: Search called the destination “Notifications”, sent all Settings results (including cached ones) to the Settings index, and discarded search state when opening a result.
- Now: “Notifications” is an alias for the canonical Reminders result; Reminders, Appearance and Data and account open their existing Settings sections. Legacy local recents are normalized and deduplicated on read. Settings section headings receive focus after the dialog closes, in both narrow and split layouts.
- Back to the originating entry reopens Search with the query, expansion and selected result restored by result identity. Arrow selection scrolls the result into view. Escape or Close dismisses the modal and returns focus to its opener or the visible search button if it was remounted. Search history is local to the mounted shell and is not persisted.

Regression evidence: model tests cover aliases, exact routes and cached aliases. Browser cases cover address, keyboard navigation, heading focus, restored query and selection, modal containment, opener focus, 320 CSS px layout, opposite-OS explicit Day and Night, and rendered Search focus indicator contrast against its surface. The official PR gate runs these cases as affected E2E tests.
