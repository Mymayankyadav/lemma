## N105.2 audited Atlas graph edits in demo, live and v6

The N105.1 owner-bound `concepts_command` is the only live write path for create, update, reparent, link, unlink, preview_merge and merge. The live adapter builds a strict v1 command envelope without any caller owner ID, uses positive optimistic concept versions, maps stale conflicts and bad owner rows to typed failures, and reuses one operationId/payload exactly when network delivery is uncertain. The server checks both source and kept versions under owner lock at merge, and returns explicit counts for affected children, prerequisites, related links, notes/cards and checkpoints.

The demo adapter adds the matching seven lifecycle methods with versioned concept state, owner-safe subject checks, parent and prerequisite cycle detection, rollback-protected transactions, preserved unrelated graph links, and merge moves of note, checkpoint and misconception references. On the flag-enabled Atlas list, an explicit edit sheet offers create/name-description/reparent/link/unlink and an owner RPC preview plus a separate confirm step before merge; all mutations refetch real graph data and surface conflicts rather than silently succeeding. Flag-off Atlas and the former read-only ImpactPreview remain unchanged.

The focused unit suites check demo mutation sequence, stale versions, cycle and owner isolation, exact RPC payload/retry semantics, no browser direct DML, and UI preview-before-merge. Work requires passing CI before the N105.2 Ready signal and merge; no production SQL in this PR.
