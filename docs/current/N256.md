## N256 · Skip neural typing work whose deadline has already passed

The tutor continues to display its count-based suggestions without waiting for neural inference. The optional neural worker shares the same 60 ms edit deadline as before. If the count-based handoff reaches the client after that deadline, it no longer sends the draft to the worker. The missed opportunity still counts in the coverage diagnostic, without storing its prompt or assigning it a model/backend. The worker also checks expiry after waiting for model preparation or a previous graph, before starting a new prefix computation. Already-running prefill is not forcibly interrupted: its completed state may still warm an exact same-epoch token prefix. Scope changes continue to discard that state.

**Measured work, not a typing-speed claim.** On main the timed client regression sent one expired draft; on this change it sends zero. In the controlled suspended-graph regression, the live prefill plus a different, expired queued edit started two prefills before, one after. The subsequent live edit still runs. The graph in these tests is instrumented, not timed neural hardware. Run `npx vitest run tests/unit/tutor/neural-worker-cache.test.ts` to reproduce, including the late same-prefix, reset and epoch cases.

**Separate baseline at 1dfe10cf.** Seven fresh local Chromium profiles typing `def` into the tutor before the dictionary was ready took a median 603 ms from worker creation to verified preload, and 596 ms from the surviving edit to its first count reply. In a separate 4× CPU desktop run of the existing virtual-key fixture (nine warm samples per editor), empty-editor tap-to-next-frame p95 was 54 ms and count-worker compute p95 was 16 ms. With eight equation chips the corresponding figures were 108 ms and 0.3 ms. These are small shared-host samples, not paired speedups or physical presentation timings.

The optional verified FP16 pack was not present locally. Installed-model on-device timing, actual display latency and any change to delivered suggestion quality or energy use remain unmeasured. No models, settings, score thresholds, deadlines, fallback behavior, learner decisions, draft storage or Undo policy were changed.
