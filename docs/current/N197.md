### Resulting receipt boundary

`command_receipts.trusted_writer_version` is added as a nullable smallint with no default or backfill. Installation aborts if the column already exists: previously writable values cannot establish trusted provenance. Historical receipts and new legacy receipts retain NULL. Only the trusted server writer can stamp version 1. The owner/operation primary key, historical DTOs, receipt replay, and retained acknowledgements after domain undo remain intact.

The migration revokes relation-level and column-level INSERT/UPDATE plus DELETE/TRUNCATE/TRIGGER from PUBLIC, anonymous and authenticated callers. It also rejects residual effective rights through inherited or switchable roles. It does not grant any client the private dispatcher schema, the provenance column, the export registry, or a broad privileged function.

The five narrow functions keep their SQL identity, argument names, return types and intended callers. Their NOLOGIN/NOBYPASSRLS owner inherits ordinary authenticated permissions and receives INSERT only on the four legacy receipt columns. It cannot stamp the provenance marker or create public objects after installation. A preexisting role must own no routine or relation in any schema, must retain no receipt UPDATE column privilege and must have INSERT only on the four legacy columns. These guards prevent unrelated callable routines or owner-rights views from exposing the new authority. Prior function owners retain EXECUTE, including historical MCP dispatchers installed under a different role.

The three original study helper implementations move to a private schema. Only the existing trusted dispatcher owner can execute them there. Public wrappers retain their signatures and route direct clients through the canonical checked dispatcher, preserving the execution context required by the timer guards. The fixture verifies different non-superuser historical-schema and cutover-installer roles.

### Export, deletion and undo

The private additional export registry now includes `command_receipts` without adding it to the domain undo registry. Browser keyset export, service owner export and stable snapshot export all include the owning user's legacy and trusted acknowledgement histories. The composite primary key supplies paging. Portable results omit only the internal `_request` and `_request_sha256` keys; raw receipt storage remains unchanged for exact replay. Other resource redactions, authorization, cursor bounds and snapshot semantics are retained. No export registry privilege is granted to clients.

Domain undo reverses domain rows and preserves the command acknowledgement. An exact retry after undo returns the historical response and cannot recreate the undone effect. Account purge removes both receipt formats for the deleted owner and preserves another owner's ledger.
