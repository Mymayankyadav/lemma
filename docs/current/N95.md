## N95 account export — registry-driven fail-closed foundation

The owner export previously omitted newer v6 tables because it maintained a static list. This change removes the list entirely and dynamically enumerates `lemma_undo_tables` with bounded 100-row registry pages; it then traverses each registered table under the signed-in user's ID, including archived projects, using existing 1000-row pagination. It records a `lemma-backup-v2` manifest of schemaVersion, registered table names and exact counts. Connector secrets are redacted and a mismatched owner row refuses export. The test double verifies new registry tables appear without frontend code changes, and 1204 rows survive pagination; a PGlite test verifies the authoritative SQL registry.

**Not Ready / blocker #1156:** current migration `20261106200000_lemma_command_registries.sql` keeps `lemma_undo_tables` RLS hidden from authenticated clients, and no read-only owner-safe registry RPC exists. The current N95 Scope does not permit a migration or server function. Until the Owner authorizes an appropriate owner-read registry path, export fails explicitly instead of silently producing an incomplete backup. No database grants or production writes are changed.

Further regressions (chat-82547#r4n8) assert the browser still has no SELECT/INSERT grant on `lemma_undo_tables`, authenticated direct reads are rejected, registry enumeration traverses more than 100 names, and an empty visible registry fails closed rather than producing a deceptively valid backup. These tests make #1156 an explicit deploy gate, not a workaround.
