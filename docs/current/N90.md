## N90 — MCP owner history, version transitions and drafts

The N91 historical corrections and N49 proposal draft commands already have registered `mcp_command` implementations. They now have explicit-instruction guidance in the MCP tutor rules (D3). Chat instructions may authorize owner-validated, undoable correction, void, proposal transition and draft actions; a revision never implicitly approves its proposal, and non-undoable writes require a preview and confirmation.

N90 adds an owner-bound `proposals_command(jsonb)` wrapper registered for `withdraw`, `revise` and `reopen`, dispatching to the unchanged N92 functions. The command uses the connector's authenticated owner claim, validates a strict envelope, optimistic version and allowed fields, returns exact operationId receipts or changed-payload/stale conflicts, and journals the parent and any successor in one undoable action. Owner-scoped MCP GET exposes proposal history and lineage without owner identifiers. The production migration requires independent SQL review.

Standalone PGlite and N94 parity regressions cover versioned transitions, exact replay, changed-payload conflicts, foreign-owner refusals, status/lineage reads, no implicit approval and undo. Unit coverage checks all three N90 resource families use the owner-bound generic dispatcher and enforce explicit instruction policy.
