**The main recommendation:** Lemma's brand is generated. The mark is a script, the emblems are a function, the colours are tokens. Extend that method to every remaining asset rather than commissioning a parallel body of hand-made artwork with its own style, licences and Day/Night variants. It is cheaper, it cannot drift, and it is the only approach that also covers Android's native surfaces, where Lottie files do not run (notifications, widgets, the launcher).

## 3. G1 · The pipeline (size M)

### 3.1 Sources (five)

| Source | File | Feeds |
|---|---|---|
| Mark geometry | `scripts/brand/lemma-mark.mjs` | Every icon, the splash, favicons, store icon |
| Emblem generator | `src/ui/v7/emblem.ts` | Covers, glyphs, notification art, empty-state marks, draw-in animation |
| Design tokens | `src/ui/v7/design-tokens.json` | CSS, Android colours and dimensions |
| Glyph set | `src/ui/v7/marks.tsx` | Action icons, shortcut icons, tile icons |
| Scenes | `tests/e2e/v7-scenes.ts` | Every screenshot: install dialog, share images, release pages, goldens |

### 3.2 Generators (five)

1. **Icon generator** (exists for the web and, since N123, for Android). Remaining: move the grid and margin rule into the adaptive *background* layer and keep ℓ and ∎ in the foreground and themed layers (today the foreground carries the whole page and the themed layer drops the ∎); a monochrome entry in the web manifest.
2. **Emblem exporter.** One function, three outputs: SVG (web, as today), PNG at a requested size and theme (Android notifications; widgets if built), and an ordered stroke list with lengths (animation). On Android the PNGs are made on the device by the web layer from the path's seed and handed to native code, so there is one implementation and no drift.
3. **Motion exporter.** From stroke order: the CSS draw-in used on the web, and an animated vector drawable for the Android splash.
4. **Scene camera.** Opens a scene at fixed data and clock, frames it (device outline, serif caption on paper or sky) and writes the image. One command regenerates the install-dialog images, the share images, the release-page image and (if widgets are ever built) their previews.
5. **Token exporter.** Tokens to `colors.xml`, `values-night/colors.xml` and `dimens.xml`, so native surfaces use the kit's exact values.

### 3.3 One manifest, one lint

`assets.manifest.json` lists every output with its source, generator, sizes, themes, byte budget and place of use. The **asset lint** checks, for every entry:

* the file exists and is newer than its source;
* it is within budget (§4);
* the mark's meaningful art is inside the platform's safe zone;
* ℓ on its background is at least 7 : 1 and an emblem's focal stroke at least 3 : 1, in both themes;
* there is no text in an icon other than ℓ;
* screenshots were captured from the current build's scenes.

**Repo fit.** Generators live in `scripts/brand/` and `scripts/v7/` (not protected). Running the lint in CI changes a workflow, which is a protected path, so wiring it in is an Owner `rules:` PR; until then it runs in `postbuild` beside `check-pwa.mjs`.

## 6. Motion: connect first, then sign

### 6.1 A1.0 · What is left after N124 (size S)

N124 built Motion v1 in CSS. Two things remain. **First**, `src/ui/v7/motion.ts` still defines eight presets that nothing calls; either adopt them where N124 did not reach or delete them, so there is one motion system. For reference, this was their intended use:

| Preset | Use |
|---|---|
| `tab` | Switching dock tabs and hub tabs |
| `detail` | Opening a path, card, session, checkpoint |
| `sheet` | Every sheet's entrance; `dismissSheet()` for the drag-to-close threshold |
| `focus` | Entering and leaving the focus screen |
| `grade` | The review card leaving after a grade |
| `completion` | Until the ∎ ships: round complete, inbox zero |
| `drag` | Calendar blocks, task reorder |
| `numbers` | `interpolateNumber()` for meters and stat tiles when a range changes |

**Second**, fire the haptic events that are defined but silent: `grade`, `gradeAgain`, `check`, `complete`, `sheetThreshold`. In the Android app they now reach the system haptics engine (N123), so this is the cheapest change to how the app feels.

### 6.2 A1.1 · Three signature motions (size M)

| Motion | Spec | Reduced motion |
|---|---|---|
| **Draw, don't slide.** Emblems stroke in on path covers (**done in N124**); still to do: the sign-in construction and the Android splash | Stroke-dash along the generator's order; 600–900 ms; the focal stroke last; once per session per cover | Final frame |
| **The ∎** | Tick → ∎ in 240 ms; on endings the square settles from 110% to 100% with one haptic thud | Final frame |
| **Stamps under the finger.** Inbox approve and reject follow the drag | Wash and stamp opacity are a function of distance (already built); add the stamp's 4° settle on release | Cut |

Everything else in the first plan's A1 list (collapsing header, list insert and remove, toast) uses the presets from 6.1.

**Budget:** no bytes added to Today's first load; no frame over 50 ms in the eight transitions at 4× CPU; one thing moves at a time; nothing loops outside Focus and the Night sky.

### 6.3 Haptics and sound

One table serves the browser and Android (`03_ANDROID_UX_PLAN.md` §5.4). Sound stays off by default as planned; if it ships, three sounds only (pencil tick, page turn, low chime), each under 200 ms and 20 KB, never on the lock screen.
