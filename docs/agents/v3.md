## Identity, claims and runtime

Read [registry contract](registry.md), current control and scoped holds first. Every execution establishes/reconciles one immutable RUN comment ID (`run:<returned-id>`) with actual `agent_id`, unique `invocation_id`, source kind, nonce, generation, timing source and verified runtime policy. Role changes retain run identity. A scheduled nominal instance is recorded only from the actual schedule; manual/external agents do not invent one.

The run records an evidenced `deadline_ceiling`, actual start, `runtime_minutes`, `handoff_minutes` and policy reference. `finish_by` cannot exceed the actual invocation ceiling or observed start plus verified runtime. No universal duration, minute slot or late-start extension exists. Unknown timing/capability permits safe reconciliation only. Checkpoint incrementally.

CLAIM binds exact run/agent, scope and overlapping paths, accepted task revision, PR/head, generation, dates and actual run finish. Fully read potentially live overlapping claims/releases/leases/holds across all execution sources. Existing valid PR holder wins; otherwise earliest eligible claim-comment ID wins after readback. RELEASE ends only the identified claim/run. Recheck authority, head, holds, requirements and expiry before every consequential action. These records are cooperative coordination, not atomic locks; an expired entitlement is not proof of process death.

## Dispatch

A claimed Lead appointment performs global intake/ref/queue/claim/reviewer reconciliation once per agreed epoch, independent of a named clock slot. Use source watermarks plus overlap/deduplication, complete pagination and periodic bounded full reconciliation; incomplete reads do not advance watermarks. A registry/packet/shared-issue writer needs its own won scope claim and immediate before/after readback.

Packets link actual registry revision/digest, control/generation and observed repository/plan/spec revisions. They contain zero or more uniquely identified tickets for actual agent/invocation pairs; zero requires an idle/blocker reason. A packet may target a subset of capacity. Each ticket has one primary action, explicit admission interval, role/playbook, task/revision, authority/capability/reviewer references, owned paths or read-only reason, continuity and one bounded fallback. Never manufacture participants to fill a packet.

Ordinary workers read guard/control, membership, assigned task/requirements/PR/handoff/playbook and scope-specific fresh facts. Match exact agent and invocation before admission. Existing admitted claims may outlive packet expiry within their own dated deadline and eligibility. New/late invocations cannot consume another invocation's ticket. Replacement packets preserve occupied claims.

Fallback order: eligible appointment under reacquired claim; named bounded fallback; canonical Task Board next-up; limited scope triage. Bound work by actual remaining runtime and recorded triage policy; do not truncate evidence for a decision. A recovery dispatcher needs a distinct won claim and no live overlapping dispatcher. Coordination outage blocks affected pushes/CLEAR/merges, while safe read-only work can continue.
