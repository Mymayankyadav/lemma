# 05 App UI (React, v7)

All values come from the shared pure core (`measure.ts`) through `src/data/adaptive`, so the app and MCP always agree. Demo mode uses seeded attempts.

## Shared primitives (`src/ui/v7`, shown in Kit `src/features/kit/V7Page.tsx`)
| Component | Spec |
|---|---|
| `ProficiencyValue` | State shown: `0.62 (0.47–0.77)` and `2 sessions`. Inferred: `~0.64 · from Sets, relations and choice`. None: `—`. Certified: ∎ mark (existing ProofEnd glyph). aria-label is a full sentence |
| `IntervalBar` | 0–1 track; 80% band and point; neutral ink (no red/green for uncertain values) |
| `StageStrip` | Four cells U S E C, each ok / fail / hinted (level digit) / not reached / unlogged; cued shown as a hollow dot |
| `KindChip` | topic, definition, result, example, technique, heuristic, control, theme, notation |
| `GapBadge` | `gap 0.26` dashed outline; `probe` when > 0.2 |
| `LinkKindChip` | equivalent, generalises, theme, uses, contrasts, analogous, part of; proposed links dashed |
| `FitMeter` | `Plan fits 87% · core 97%`, with required vs available minutes; neutral ink above 0.8, accent below |
| `CardBudget` | `New cards 1/3 today` plus a 30-day review-load sparkline |
| `EstimateRange` | `45–90 min` (p10–p90 of the lognormal) instead of one number |

## Screens
**Atlas** (`src/features/atlas/v7/AtlasV7.tsx`, `AtlasMap.tsx`, `model.ts`, `scene.ts`)
- **Node encoding:**
  - certified facets as ring segments;
  - halo opacity grows with sd;
  - gap gives a dashed outline;
  - stale (> 30 days) fades.
  - Existing statuses are kept.
- **Filters:** uncertain, gaps, certified, stale, kind.
- **View switch:** Map | Themes | Bridges.
  - **Themes:** list → theme → instances, each with its profile row.
  - **Bridges:** subject graph; line width ∝ strength mean; dashed when there are no opportunities. Tap shows opportunities and uses.
- **Concept sheet** (peek shows whole rows, per N161):
  - Facets: a row per facet with value, interval and sessions.
  - Gap: badge plus "Copy probe prompt".
  - Links: typed; proposed ones carry approve/reject.
  - Recent attempts: last 5, each with a StageStrip.
  - Kind: select, editable, undoable.

**Progress** (`src/features/insights/v7/ProgressV7.tsx`, `progressModel.ts`). New Atlas section:
- **Area profile table:** rows = systems; columns Knowledge, Select, Execute, Transfer, Evidence. Tap → planets.
- **Track record:** one-step log loss of the served model, PFA and the base rate over the last 200; bucket chart (predicted vs observed); banner `Model below baseline — simple estimates in use` when D1 fails.
- **Your calibration:** confidence Brier (reliability, resolution, overconfidence); hidden under 20 rated attempts.
- **Model health** (01 §9): one row per stream (attempts, cards, durations, attendance) with D1–D5 pass/fail, the log-loss gain over the baseline and the calibration slope. A failure names its action, e.g. `Card predictions overconfident → recalibrating`.

**Checkpoint** (`src/features/checkpoint/v7/CheckpointV7.tsx`)
- **Ready panel:** for the criterion facet of each primary concept, P(clean pass on the criterion) and status: certified / needs delayed evidence / needs uncued attempt / not yet. Each status names the single missing requirement.
- The evidence list (`src/features/project/v7/Evidence.tsx`) shows StageStrip, hint, cued and error tag.

**Today** (`src/features/home/v7/V7Today.tsx`, `todayModel.ts`)
- Queue badges: practice, stretch (with time box), probe (with reason, e.g. "decision close · Compactness execute"), recheck, retry.
- Frustration state line: `Easing off — next 3 practice`.
- Session template order: Checks → Learn → Practice → Close; `Welcome back · 3 quick checks` after > 3 study days away.
- `FitMeter` and `CardBudget` in the header.

**Path** (`src/features/project/v7/V7Path.tsx`, `pathModel.ts`)
- CP rows show `EstimateRange`, tier and `test-out available` when P(test-out) ≥ 0.7.
- Pace line: `You take ~2.9× estimates (14 CPs)`.
- Skipped `cards` CPs fold into a "converted" note.

**Plan proposal** (`src/features/plan-proposal/v7`)
- A CP shows template sections (Prepare, Teach, Practice, Criterion, Stretch, Close) and a card plan per KC.
- Validation errors appear inline and block approval.
- **Conversion view** (kind `plan_conversion`): old → new CP table, skipped CPs with reasons, card counts as keep / revise / suspend / new. One approve per project.

**Planner and calendar** (`src/features/planner`, `src/features/calendar`)
- Each new block offers the top 2 slots (10 §9), each with `kept 4 of 5 recent` evidence. Choosing, moving or skipping a block is logged as a fact.
- The day's queue lists the KG reason per item, e.g. `+0.6 pts/10 min · Compactness memory`.

**Proposals** (`src/features/proposals`): a new card type, link proposal (from → to, kind, direction, rationale, confidence). Swipe works as now, plus "approve all of this kind".

**Settings** (`src/features/settings`). New Atlas group:
- mastery threshold (0.80–0.95, default 0.85);
- stretch share (0–25%, default 20%);
- plan-first minimum minutes (default 10);
- ask confidence before problems (default on);
- card quota share (25–100%, default 50%); card cap (5–40% of a block, default 12.5%); card weight in the exam utility (default 0.4);
- read-only line: `You study 78% of declared time (14 days)`.

**Session** (`src/features/session`): the attempt list shows a StageStrip per attempt; legacy attempts are labelled "legacy".

**Review**: card FSRS untouched. Card info shows its KC, facet and kind; suspend and split proposals appear in Proposals.

## Data layer (`src/data`)
- **`types.ts`:**
  - `AtlasGraph.concepts[]` gains `kind`, `facets: {facet, p, lo, hi, sessions, state:'shown'|'inferred'|'none', certified, inferredFrom?}[]`, `gap?: {p, lastAt}`;
  - `links[]` gains `kind`, `status`, `strength?: {mean, o, u}`;
  - new `AreaProfile`, `TrackRecord`, `ThemeView`, `BridgeView`, `AttemptView`;
  - new `Feasibility {pAll, pCore, required, supply}`, `CardBudget {quota, used, load30[]}`, `PlanTemplate`, `ConversionView`.
- **`api.ts` / hooks:**
  - `getAreaProfile(id)`, `getTrackRecord()`, `getThemes()`, `getBridges(subjectId)`;
  - `decideLink(id, approve)`, `setConceptKind(id, kind)`, `updateAtlasSettings(patch)`, `listAttempts(filter)`;
  - `getFeasibility(projectId)`, `getCardBudget()`, `getConversion(proposalId)`.
- **`adaptive/{contract,live,demo}.ts`:** load facts and call `replay`; memoise on `settings.facts_epoch`.
- **`sync/keys.ts`:** keys for profile, track, themes, bridges and attempts. Invalidate on facts_epoch.

## Copy rules
Numbers always come with an interval and a count. "Inferred" is never shown as measured. There are no grades or colours for uncertain values.

## UI tests
- Unit: state formatting (shown / inferred / none); certification status text; card ≤ 100 tokens.
- e2e (`tests/e2e/v7-atlas-v2.spec.ts`): sheet facets; Themes and Bridges views; profile table; model-health banner; link approve; settings persist; 360/390 px phones at large text.
- e2e (`tests/e2e/v7-plan-v2.spec.ts`): template sections and inline errors; conversion approve and undo; FitMeter and CardBudget on Today.
- Parity: app values equal MCP values on the fixture, including P_all, P_core and the quota.
