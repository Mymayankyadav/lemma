# Lemma on Android — build and test (ANDROID-01)

This is the Capacitor 8 native **debug** package for the existing Lemma web source. The generated Android project is committed in `android/`; bundled web assets in `android/app/src/main/assets/public/` are generated by `npm run android:sync` and must not be committed. No JavaScript or FSRS rewrite is involved.

## Prerequisites

- Node.js 22 with npm and the checked-in `package-lock.json`.
- JDK 21 (the CI workflow uses Eclipse Temurin 21).
- Android Studio 2025.2.1 or newer and an Android SDK, including API 36 for this scaffold's `compileSdkVersion` (install through Android Studio SDK Manager).
- Android USB debugging enabled for ADB installation, or a trusted device installer for APKs.

The official [Capacitor 8 Android setup](https://capacitorjs.com/docs/v8/getting-started/environment-setup) and the project's `android/variables.gradle` establish the Android toolchain requirements.

## Reproducible local build

From the repository root:

```sh
npm ci
npm run android:sync
cd android
./gradlew assembleDebug
```

The resulting APK is `android/app/build/outputs/apk/debug/app-debug.apk`. On Windows, run `gradlew.bat assembleDebug` instead. Do **not** run `npm run android:add` in a checkout that already contains `android/`: it is a one-time scaffold operation.

`npm run android:sync` rebuilds `dist/` and copies the current source into the native app; run it after every web source change before building. The checked-in application ID is `io.lemma.study`. The GitHub Actions workflow injects public `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY` repository variables at build time. For local authenticated builds, set those public variables in your shell before `npm run android:sync`; never use a Supabase service-role/secret key in an APK.

## GitHub Actions and sideloading

The [Android workflow](../.github/workflows/android.yml) runs on pull requests and `main` pushes. It performs `npm ci`, syntax/plan/lane checks, Capacitor sync and `./gradlew assembleDebug`, then uploads the `lemma-android-debug` artifact. Open the workflow run in GitHub Actions and download/extract that artifact to get `app-debug.apk`.

Install with ADB:

```sh
adb devices
adb install android/app/build/outputs/apk/debug/app-debug.apk
```

For an APK downloaded from CI, replace the path with the extracted `app-debug.apk`. A debug APK uses a debug signing key, **not** a release key. Separate CI runners can produce debug APKs with different signing certificates, so a later APK might refuse an in-place update. Do not uninstall an existing Lemma installation without first safely exporting or synchronizing any unsaved/local-only study data. Release signing and in-place update delivery are future work, not established here.

## Current scope and verification

- S1 added the native Android project and reproducible **debug APK** CI. S2 adds native Back handling and resume logging. Native Google OAuth callbacks, notifications, and further device lifecycle changes are later slices.
- A successful Gradle build is **not** proof of launch, live Supabase auth/sync, or installation on a physical phone. The physical device gates remain outstanding.
- Deploying GitHub Pages does **not** update bundled assets of an installed APK. Each new bundled release requires building and installing a correctly signed updated APK.
- Use a separate test device or export first when evaluating debug builds with important local flashcards; never clear storage or uninstall as a troubleshooting shortcut.

## Android Back and resume (ANDROID-01 S2)

The pinned `@capacitor/app@8.0.0` matches Capacitor core. `npm run android:sync` links the native Android App plugin. The inline app code uses `window.Capacitor.registerPlugin('App')` only when running on the native platform and when the plugin is available; it registers nothing in ordinary browsers.

On the Android Back gesture or hardware button, Lemma closes an open sheet first, then returns secondary app screens to Home using the existing router (which does not push browser history). At Home, it calls `history.back()` if the native event reports prior history, otherwise `App.exitApp()`. The `resume` event is logged for diagnosis, but does not force sync or mutate data; existing foreground logic remains responsible.

`npm run test:android` checks these decisions with mocked bridge events. Physical-device Back, resume and offline-data verification are still pending. Never uninstall an app with unsaved local data as a workaround.


## Shared ANDROID-02 / RELEASE-01 device acceptance protocol (PREPARATION ONLY)

**Status:** test design, not device evidence. Do not run this sheet until the relevant N1–N3 features are merged with green checks. UI-01 must be complete before ANDROID-02 implementation begins. A debug APK alone never satisfies these checks. Reuse unchanged phone/Pages results for RELEASE-01 rather than asking the owner to repeat them.

### Preconditions and safe setup

1. Record tested git SHA, successful Android build run/artifact ID, installed Android/OS version, installed Lemma version and the Pages deployment SHA. Never confuse `main` with a stale downloaded APK. If any artifact changes, identify exactly which checks are invalidated.
2. Before replacing an installation, back up any device-only cards/review history with the existing export feature and verify the exported file is accessible. Do **not** uninstall, clear app storage, force a workspace transfer or discard an outstanding write to fix a test. An APK may be signed with an incompatible debug key; stop the upgrade check rather than risking local data.
3. Use a small labeled fixture such as `ANDROID-02 own-device smoke` in the tester's **own opted-in** account workspace. Verify the selected workspace first; never auto-enroll anonymous cards. Avoid real private study content in screenshots/logs. No service-role key, extra production identity or destructive fault injection is required.
4. Test a phone and an independent browser on Pages belonging to the **same owner**, plus temporary offline mode on the phone. Record local time, connectivity, visible status and whether data was actually committed remotely. Label all simulated/emulator/CI evidence separately from physical-device results.
