# 15. Tutor signals: what to ask the tutor for, and how to use it

**Status:** plan only, 21 November 2026.

The tutor is the LLM that already reads the checkpoint, the question and the book pages. This file covers:

- what signals to get from it
- how to get them without slowing down typing
- the different ways to feed them into the spatial model and n-gram decoder
- crude estimates of the gain from each, to be replaced by measurements on your history

## 15.1 Short answer

- **What to ask for:** a **checkpoint context pack**, sent once per checkpoint and cached on the phone. It holds the checkpoint's terms, notation and conventions, named objects, likely LaTeX commands and hard-to-spell names, all taken from the question and the book pages.
- **Where it plugs in:** the decoder uses the pack in three places:
  - a soft probability boost, applied only once the learner has started typing the word
  - a two-tier search: the pack's words first, then the full lexicon
  - protection and correction rules for names and notation
- **Crude expected gain, on top of the math lexicon and n-gram:**
  - listed terms reach the top 3 about 1–2 letters sooner
  - roughly 3–9% fewer taps overall
  - false corrections of question-specific names fall to near zero

  These are guesses, worked out in §15.6.
- **What not to use:** words from the tutor's solution. They would give the largest gain, and they are a hint list, so they stay off (§15.4).
- **Before building the LLM path,** test two free baselines that need no LLM:
  - the question text used as a cache
  - keyphrases extracted from the book pages

  The tutor's pack has to beat them to be worth its complexity.

## 15.2 Signals the tutor can provide

| Signal | Example | Source | Risk | Used for |
| --- | --- | --- | --- | --- |
| Checkpoint terms | sequence, bounded, supremum, Cauchy | Question, book pages | Low | Boost, two-tier search |
| Multi-word terms | uniformly continuous, open cover | Question, book | Low | Phrase completion after the first word is typed |
| Named objects in the question | `f`, `(x_n)`, `A`, `\varepsilon` | Question | Low, but only after a typed prefix | Identifier completion; never to fill an operand slot (07 B2) |
| Notation conventions | `⊆` means subset-or-equal in this book; the book writes `\varepsilon` | Book, question | Low | Convention prior from the first answer onwards |
| Likely LaTeX commands | `\lim`, `\sup`, `\mathbb{N}`, `\varepsilon` | Question, book | Low | Command prior; context symbol palette |
| Proper names and theorem names | Bolzano–Weierstrass, Lipschitz | Question, book | Low | Never autocorrected; boosted when being spelled |
| Likely misspellings of hard names | Lipshitz, Weierstras | Generated by the LLM | Low | Correction pairs for the noisy channel |
| Topic | real analysis; sequences and series | Checkpoint | Low | Topic weights for the n-gram mixture |
| Expected answer format | prose proof, computation, short answer | Question | Low | Keyboard page prior (letters vs math) |
| New terms in a tutor reply | Words the visible reply introduces | Visible tutor message | Low | Updates to the pack |
| Solution terms | triangle inequality, Archimedean property | Tutor's solution | **High: these are hints** | Not used (§15.4) |

## 15.3 How to get the signals

No LLM call ever happens per keystroke. The tutor isn't callable while the learner types, and specification §4.4 forbids any cloud call that blocks typing.

| Channel | How | When | Cost | Notes |
| --- | --- | --- | --- | --- |
| A. Checkpoint context pack (new; recommended) | Host instructions ask the tutor to build the pack from the question and the pages it already reads with `read_pages`, and send it with its first reply | Once per checkpoint, cached on the phone | About 300–800 output tokens, once | No database migration: reuse PR #1738's tagged reply-body suffix, or store it locally |
| B. Per-reply update | Extends the PR's `writingAid` v1 metadata: new terms or notation that this visible reply introduces | Each tutor reply | About 50–150 tokens | Same check as the PR: every item must occur in the visible reply |
| C. Offline batch, for evaluation | A script you trigger asks an LLM for packs for your past checkpoints, from the question and pages only, never your answers | Once | Small | Sends book text and questions to the LLM, so only with your approval |
| D. No-LLM baselines | (D1) question text and visible tutor messages as a cache document; (D2) TF-IDF or YAKE keyphrases (Campos et al. 2020) from the book pages, compared with the general math corpus; (D3) the book's index or glossary, if it has one | At checkpoint open | None | The bar the LLM has to beat |

If no pack exists, because the tutor is offline or on an older version, the keyboard simply behaves as it does without one.

## 15.4 Rules for the signals

1. **Visible sources only.** Every term, identifier and name must appear in something the learner can see: the question, a visible tutor message, or the book pages. The app checks each match and records where it was found.
   - Misspelling pairs are the one exception. They are generated, but they only map to a term that was itself checked.
2. **Roles decide use.**
   - Question, book and visible-tutor items are usable for prediction and correction.
   - Hint, proof and solution items are never used for prediction.
   - Using solution items **only to fix the spelling of a word the learner has nearly finished** (at least 5 typed letters, edit distance at most 2) is your decision, off by default.
3. **The tutor's labels are untrusted.** This is the PR's rule: calling a proof step "suggested wording" grants it nothing.
4. **The tutor's salience is a feature, not a probability.** LLM confidence words aren't calibrated, so the boost strength is learned from replay (§15.8).
5. **Size limits:**

   | Item | Cap |
   | --- | ---: |
   | Terms | 200 |
   | Multi-word terms | 50 |
   | Notation items | 50 |
   | Identifiers | 30 |
   | Names | 30 |
   | Commands | 40 |
   | Misspelling pairs | 30 |

   Anything over the limits is dropped, never truncated mid-item.
6. **Packs expire** when the checkpoint or its revision changes.
7. **No boost before the learner starts a word.** At prefix length 0 (pure next-word prediction), pack words get no boost. This keeps the pack a completion aid rather than a suggestion of what to write, and it lines up with the learner-choice rule (07).

## 15.5 Ways to integrate it

The decoder you were about to build scores each candidate word *w* as:

> log P(taps | *w*) + λ · log P(*w* | previous words) + pack terms

Each option below changes the pack terms or the search.

| # | Integration | Mechanism | Crude effect | Risk |
| --- | --- | --- | --- | --- |
| I1 | Soft boost | Add λ_c(*p*) for words in the pack, rising with typed prefix length *p* (0 at *p* = 0). This is contextual biasing, as speech recognizers do with contact names (Aleksic et al. 2015; Pundak et al. 2018). | Listed words' rank divided by roughly the boost factor (§15.6) | Over-boosting pushes unlisted words down; λ is learned |
| I2 | Two-tier search | Search the pack, function words and your personal vocabulary first (3,000–7,000 words); search the full lexicon only if tier 1's best posterior is weak | 15–60× fewer candidates in the first pass; faster decoding | Small, because the full lexicon remains the fallback |
| I3 | Hard restriction | Search only the pack and function words | Fastest | Unlisted words become unreachable. Not recommended on its own |
| I4 | Cache document | Question, visible replies and book pages become a cache model mixed into the n-gram (Kuhn & De Mori 1990; topic and cache adaptation: Iyer & Ostendorf 1999; Bellegarda 2004) | Likely most of the gain, with no LLM | Same over-weighting risk; mixture weight learned |
| I5 | Correction priors and protected names | In-pack words become likelier corrections; names and identifiers are never autocorrected; LLM misspelling pairs feed the noisy channel | False corrections of names fall to near zero; more misspelled terms fixed | Over-correction into pack words; the certified threshold still applies |
| I6 | Convention priors | Start the convention counts (11 §11.3) from the book's conventions | Right variant from the first answer | Small |
| I7 | Command prior and context palette | Commands in the pack rank first after `\`; a one-tap row shows the checkpoint's 5–8 symbols, drawn from the question's notation only | Saves page switches and searching | Only question and book notation, so the palette shows no answers |
| I8 | Keyboard-page prior | The expected answer format and the pack's math density set the starting page | Saves an occasional page switch | Small |
| I9 | Topic weights | The topic selects mixture weights between topic-specific n-gram statistics | Modest perplexity gains | Wrong topic label; falls back to the global model |
| I10 | Restricted output layer | The neural model (CIFG) computes scores only for the active vocabulary | About 1.7–2.9× faster per step (§15.6) | Approximate normalization; check ranking parity |
| I11 | Tap-decoder guidance | Beam pruning in the spatial decoder favors pack words for ambiguous taps | Fewer wrong decodes on sloppy taps of pack words | Same as I5 |

## 15.6 Crude estimates

Every number here is a guess, to be replaced by replay on your history (§15.8).

**Boost math.**

- Let *m* be the probability mass the base model already gives the pack's words at a content-word position, and *h* the fraction of times the learner's word really is in the pack.
- Boosting pack words by β and renormalizing, the best β is h(1 − m) / (m(1 − h)).
- At that β:
  - a pack word's probability is multiplied by h/m
  - an unlisted word's probability is multiplied by (1 − h)/(1 − m)
  - the average gain in log-probability per content word equals the KL divergence between Bernoulli(h) and Bernoulli(m)

| h (pack hit rate) | m (mass already expected) | Best β | Pack word × | Unlisted word × | Gain per content word |
| --- | --- | --- | --- | --- | --- |
| 0.3 | 0.1 | 3.9 | 3.0 | 0.78 | 0.15 nats |
| 0.5 | 0.1 | 9 | 5.0 | 0.56 | 0.51 nats |
| 0.6 | 0.1 | 13.5 | 6.0 | 0.44 | 0.75 nats |
| 0.5 | 0.3 | 2.3 | 1.7 | 0.71 | 0.09 nats |
| 0.8 | 0.2 (solution list, not used) | 16 | 4.0 | 0.25 | 0.83 nats |

What the table shows:

- The gain depends on two things only:
  - how often the pack is right (*h*)
  - how little the base model already expected those words (*m*)
- A strong base model (high *m*) leaves little to gain.
- Both numbers can be measured on your history in an hour.

**Rank.** If competing words' scores fall roughly like 1/rank (Zipf), multiplying a word's score by *f* moves it from rank *r* to about *r*/*f*. With *f* around 3–6, a pack term at rank 10 after two letters moves to about rank 2–3, so it enters the top 3 about 1–2 letters sooner.

**Taps per 100 words.** This assumes a math-heavy proof answer of about 650–700 taps, including page switches.

| Source | Assumption | Taps saved |
| --- | --- | --- |
| Pack terms | About 25 math terms averaging 9 letters, with h = 0.5–0.6: about 12–15 listed occurrences, each completed 1–2 letters sooner | 12–30 |
| LaTeX commands | 5–10 occurrences, each 1–2 taps sooner with the command prior | 5–20 |
| Context palette | 3–6 symbols taking 1 tap instead of 3–5 | 6–24 |
| Unlisted words pushed down | 10–13 occurrences, 0–1 letter later each | −3 to −8 |
| **Net** | | **about 20–66 taps, roughly 3–9% of taps** |

This is in addition to whatever the math lexicon and n-gram already save.

**Top-3 success for pack terms after two letters:** perhaps 50% → 70–80%. Top-1 accuracy perhaps 25% → 45–55%. Both are guesses.

**Search space.**

- The full math lexicon has 100,000–200,000 word forms; tier 1 has 3,000–7,000.
- After two typed letters, that's roughly 300 versus 7 candidates per prefix on average. The distribution is very uneven, so this only illustrates the scale.

**Speed (I10).** In Gboard's CIFG, the output layer accounts for about 0.96M of the 1.4M multiply-adds per step. Scoring a 4,000-word active vocabulary instead of the full one makes each step:

- about 1.7× faster with a 10,000-word vocabulary
- about 2.9× faster with Lemma's planned 20,000-word vocabulary

**Autocorrect.** Names and identifiers in the pack become protected, so false corrections of question-specific names fall to near zero.

**Solution terms.** The last row of the table shows why they're tempting. It's also why they stay off: they would be a list of hints. Predictive suggestions measurably steer what people write (Arnold et al. 2020).

## 15.7 Headline guesses

| Option | Gain | Effort | Recommendation |
| --- | --- | --- | --- |
| D1: question text and visible tutor messages as a cache | Probably most of the vocabulary gain | Small, no LLM | Do first |
| D2: keyphrases from book pages | Adds chapter terms | Small, no LLM | Do second |
| A: LLM context pack | Adds notation conventions, names, misspellings, multi-word terms and roles beyond D1/D2 | Medium | Only if it beats D1 + D2 by at least 1 point of keystroke savings, or clearly reduces notation and name errors |
| I2 + I1 + I5 + I7 | The integration of whichever source wins | Medium | Yes |
| Solution-aware signals | Largest gain on paper | — | No |

## 15.8 Checking it quickly on your history

You don't need new data; your past checkpoints already have questions, pages and your answers.

1. **Build three context sources** for each past checkpoint:
   - D1 from the question text
   - D2 from the pages
   - the LLM pack from the question and pages, never your answer
2. **Replay your actual answers** through the decoder (02 §2.5) under four conditions:
   1. no context
   2. D1
   3. D1 + D2
   4. D1 + D2 + LLM pack
3. **Measure:**
   - *h* and *m* (§15.6)
   - top-1 and top-3 accuracy at prefix lengths 1–3, separately for listed and unlisted words
   - keystroke savings
   - false corrections
   - learner-choice leaks (must stay 0)
4. **Fit the boost strength** and the prefix gating on the earlier half of your history; test on the later half.
5. **Size:** about 2,000–4,000 word positions detect a 2-point difference (02 §2.10).

## 15.9 Live check

Turn the pack boost on or off at random for each answer (50/50), and compare keystroke savings, acceptance, false corrections and attention cost from the logs (03). Because the boost applies only after a typed prefix, steering risk is low. Still watch your vocabulary diversity with and without it over 2–4 weeks.

## 15.10 Risks

| Risk | Mitigation |
| --- | --- |
| The LLM invents terms that aren't in the source | Visible-source check (§15.4 rule 1) |
| Over-boost hides unlisted words | Prefix gating, learned λ, two-tier fallback |
| Steering what the learner writes | No boost at prefix 0, no solution terms, diversity monitoring |
| Stale packs | Expire on checkpoint or revision change |
| Older clients display the metadata | The compatibility limitation the PR already noted |
| Book text sent to the LLM | Already happens when the tutor reads pages; offline batches only with your approval |
| Tutor unavailable | Cached pack, or behave exactly as without one |

## 15.11 Order

1. D1, the cache document, plus replay on your history.
2. D2, book keyphrases.
3. An offline LLM pack batch for history evaluation, compared against D1 + D2.
4. Integrate the winner into the decoder: I2, I1 with prefix gating, I5, I6, I7.
5. Build the in-band pack channel (A and B) only if step 3 shows the LLM adds enough.
6. Run the live randomized check.
